# 두 로봇 3점 선승 반복 시험 (2026-11-28)

성공 기준은 기존 영상 심판으로 실제 경기를 진행해 한 팀이 3점을 먼저 얻는 것이다.
중앙 배치 외에는 공을 옮기지 않으며, 로봇 참 위치를 제어 입력으로 주지 않는다.
득점 한 번, 단순 이동 완료, 평가 점수 상승만으로 경기 성공이라고 판단하지 않는다.

## 공통 코드 수정

- 공 뒤 목표가 외벽/골대에 들어가는 경우: 스트리밍 전술 목표를 이동 가능한 인접 위치로 조정.
  고정 GoToPose의 성공 위치는 임의로 바꾸지 않는다.
- 자유로운 현재 좌표가 격자 반올림으로 장애물 셀에 연결돼 A*가 실패하는 경우:
  보이는 이웃 셀에 시작점을 연결한다. 보수적인 셀 여유는 줄이되 실제 몸체 정지 예측 검사는 유지한다.
- 공 접근 시 정렬된 전방 접근과 몸체를 돌려 우회하는 경우의 공 여유를 구분한다.
  공을 돌아갈 때 뒤쪽 몸체가 공을 건드리지 않도록 전체 몸체 기준 여유를 사용한다.
- 이동 명령이 있지만 1초간 유효한 이동 진전이 없으면 원인/횟수를 기록한다.
  위치 추정값의 흔들림만으로 진전을 인정하지 않고 바퀴 피드백도 확인한다.
  공 목표와 별개로 전후진·회전 후보를 모터 모델로 평가하고 공간이 넓어지는 짧은 탈출을 수행한 뒤 재계획한다.
  탈출도 막히면 후보 방향을 바꾼다. 유효한 위치/센서가 없거나 물리적으로 통과 불가능하면 명령을 강제하지 않는다.
- 전술 접근 지점 도착 후 다음 행동으로 이어지지 않는 정체도 감시한다.
  완료된 고정 GoToPose는 기존처럼 완료를 유지한다.
- 가까운 공을 밀 때 거리만 보고 끊지 않는다. 기존 HLS의 하단 원호 방향 관측을
  `world_model/ball_contact`로 전달한다. 새 거리값을 만들어 넣거나 기존 거리 보정식을 변경하지 않는다.
- 유효한 하단 공 관측이 이어지면 밀기를 유지한다. 공 관측이 완전히 끊겼을 때의 제한된 밀기/재관측은 유지한다.
  재관측 후진도 2초 이상 같은 목표를 무한히 쫓지 않는다.
- 로봇은 움직이지만 공이 골대 쪽으로 8초간 진전하지 않으면 반대 측면으로 재접근한다.
- 공 접촉 전 상대 속도를 낮춘다. 정지한 공의 범퍼 근처에서는 초기 상대 접근 속도 0.06m/s를 사용하고,
  공이 함께 구르면 관측된 공 속도에 맞춰 다시 가속한다. 이 값은 실측 식별값이 아닌 초기 설계값이다.
  먼 거리의 바퀴 속도/가속 한계는 기존 정격 90% 설정을 유지한다.
- 공 높이보다 높은 수평 LiDAR의 포인트를 공 주변이라는 이유로 지우지 않는다.
  해당 포인트가 상대 범퍼일 수 있으므로 충돌 검사에 보존한다.
- 공격 경기에서는 OUT 이후도 복귀→READY→중앙 공 배치 순서로 처리한다.
  수동 START는 유지한다. 실물에서는 중앙 공 배치를 사람이 수행한다.

## 심판 공 보조 옵션

`referee_ball_assist:=true`이면 유효하고 최근의 영상 심판 관측을, 로봇 자체의 거리 관측이
0.5초 이상 끊긴 경우에만 기존 공 필터에 보조 입력한다. 기본은 false이다.
심판 카메라의 실제 영상 추정치이며 시뮬레이터 참 위치를 넣지 않는다.
로봇 자체 위치는 기존 LiDAR/IMU/odom 추정을 계속 사용한다.
출처는 `world_model/ball_contact` JSON의 `metric_source`에 표시된다.
실물에서도 같은 코드/옵션을 사용하되 카메라 보정·좌표계와 시각 동기화가 유효해야 한다.

## 평가식

강화학습이나 자동 가중치 학습은 하지 않는다. 경기별 같은 식으로 기록을 다시 계산하고,
실패 장면의 원인을 찾아 수동으로 코드를 수정한다. 버전2 평가식은 다음과 같다.

- 득점 +100, 실점 −100
- 아웃/관측 불명 이탈 −10 (마지막 접촉자를 확정할 수 없어 양쪽에 동일 적용)
- 1초를 넘긴 정지 시간 −5/초
- 골대 쪽 공 전진이 5초 이상 없는 시간 −1/초
- 플레이 시간 −0.2/초, 이동 거리 −0.5/m, 탈출 시도 −2/회
- 공에서 0.45m 넘게 떨어진 시간 −0.2/초, 0.20m 안의 시간 +0.1/초

시간·전진 정체 감점으로 공 주변을 무의미하게 돌기만 해도 점수가 올라가는 것을 막는다.
경기 양쪽 점수 합은 득점/실점 보상이 상쇄돼 움직임 효율을 비교하는 보조 지표다.
이 휴리스틱 점수는 실제 축구 능력의 검증된 척도가 아니다. 3점 선승 완료가 별도의 필수 기준이다.
벽 접촉 횟수나 마지막 접촉자를 추측해서 측정값처럼 채우지 않는다.

## 실행/자료

```bash
cd ~/pinky-soccer/.worktrees/attack
source /opt/ros/jazzy/setup.bash
source install/setup.bash
ROS_DOMAIN_ID=193 ros2 launch pinky_soccer_viz attack.launch.py \
  mode:=mujoco robots:=2 referee_ball_assist:=true
```

시험 드라이버는 별도 터미널에서 `scripts/verify_attack_match.py --output <폴더>`로 실행한다.
`ROS_DOMAIN_ID=193`에서만 동작하며, 두 로봇의 준비와 중앙 공 관측 확인 후 1초 뒤 START를 보낸다.
일반 launch나 실물에서 자동 START를 실행하지 않는다. 시험 종료 시 STOP을 보낸다.
`scripts/analyze_attack_matches.py`는 모든 판을 동일한 버전2 평가식으로 다시 비교한다.
원시 토픽과 실패 판은 `docs/validation/attack_match_1`부터 순서대로 보존한다.

## 확인된 한계

반복 시험의 최종 수치/판정은 `docs/validation/attack_match_scores.json`을 확인한다.
초기 판은 아웃 후 공이 로봇에 가려 재개가 막혔고, 후속 판은 단독 득점/복귀/재개에는 성공했지만
공 주변 무의미한 움직임 또는 장기 정체 때문에 3점 선승을 끝내지 못했다.
공 정면 유지용으로 추가 실험한 조향은 진행을 늦춰 최종 코드에서 제외했다.
실물 주행, 벽 접촉 계측, 다양한 시작 위치/노이즈에서의 성공률은 미검증이다.
기존 보정 원본·MPC·공식 서브모듈·Gazebo는 이번 반복 시험에서 변경하지 않았다.

### 탈출 중단 버그의 재현과 수정

기존 탈출의 진입 조건인 '1초 정체'를 탈출 중에도 재검사해서, 로봇이 8mm 이상 움직이면
진전 시각이 갱신되고 다음 제어 주기에 탈출을 중단하는 문제가 있었다.
진입 조건은 비활성 탈출에만 적용하고, 활성 탈출은 매 주기 충돌 검사 하에 예정 구간을 지속하도록 수정했다.
그 상태를 재현한 회귀 테스트가 통과했다. 판7/8 로그의 사례 비교는
`docs/validation/escape_regression.json`에 있다. 수정 후 약0.57초/5.8cm 지속된 탈출을 확인했다.
두 판의 초기 조건이 완전히 같은 것은 아니므로 이 수치를 일반 성능 향상률로 해석하지 않는다.
탈출 버그 수정이 3점 선승 경기 완성을 의미하지는 않는다.


### 공 뒤에서의 정렬과 시험 드라이버 보정

공 뒤 위치는 맞고 방향만 부족한 경우에는 `AlignToBall` 목표로 현재 위치에서 방향만 맞춘다.
새 제어기를 추가하지 않고 기존 추종기의 방향 정렬과 충돌 검사를 재사용한다.
위치가 이미 맞는데 15cm 뒤 접근점을 다시 쫓으며 공 주위를 도는 상황을 줄이기 위한 구분이다.
`robocup_demo`의 접근/정렬/킥 단계 분리와 같은 판단 원칙을 차동구동에 맞춰 적용했다.
방향이 맞으면 즉시 PushBall로 이어지는 회귀 테스트를 추가했다.

판9의 두 번째 득점 후에는 시험 드라이버가 이미 끝난 랠리의 제한 시간에 복귀 시간을 더해
경기를 중단한 문제가 발견됐다. 원래 결과 문자열을 보존하고 INVALID TEST로 표시했다.
실제 이벤트는 노란 팀2점/파란 팀0점이며, 3점 경기를 완료한 것은 아니다.
수정 드라이버는 GOAL/OUT 이벤트에서 랠리 타이머를 해제하고 다음 START에서 새 타이머를 시작한다.
