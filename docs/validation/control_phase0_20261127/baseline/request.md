# Pinky Soccer 이동 제어 시스템 개선 및 다중 GoToPose 제어기 개발·성능 비교

## 1. 프로젝트 목적

현재 개발 중인 Pinky Soccer 프로젝트의 이동 제어 시스템을 개선한다.

프로젝트는 차동구동 방식의 Pinky Pro를 활용한 1대1 자율 로봇 축구 시스템이며, 실제 로봇, MuJoCo, Gazebo에서 공통 알고리즘을 사용하도록 개발하고 있다.

현재 자기 위치 추정, 공 인식, 상대 로봇 인식 및 World Model을 개선하고 있다. 이를 기반으로 다음 단계에서는 이동 제어의 정확성, 신속성, 연속성 및 실시간성을 확보한다.

기존 GoToPose는 NMPC를 이용하여 경로 생성, 장애물 회피, 속도 계획 및 제어 입력 계산을 동시에 수행하는 구조이다.

하지만 현재 다음과 같은 문제가 관찰되거나 우려되고 있다.

- 실제 로봇 주행 중 전진과 감속이 반복되는 버벅임
- 장애물 회피 경로 생성 성능 부족
- 목표점 주변에서 반복적인 전후진 및 좌우 방향 보정
- 목표점 도달 이후 성공 판정까지 발생하는 긴 지연
- 센서 기반 추정값의 변동에 따른 경로 및 제어 입력 불안정 가능성
- 경로 재생성 과정에서 발생할 수 있는 참조 궤적 불연속
- NMPC의 반복적인 최적화에 따른 연산 부담과 실시간성 저하 가능성
- 개별 행동 사이의 불필요한 정지 및 재출발

이번 개발의 목적은 특정 제어기가 우수하다고 미리 가정하는 것이 아니다.

기존 제어기의 문제를 먼저 해결하고, 개선된 NMPC와 여러 경량 제어 방식을 추가한 뒤 동일한 조건에서 정량적으로 비교하여 Pinky Soccer에 가장 적합한 이동 제어 방식을 결정한다.

최종적으로 다음 다섯 가지 성능을 동시에 추구한다.

1. 빠른 이동
2. 정확한 위치 및 자세 제어
3. 낮은 연산 부하
4. 자연스럽고 연속적인 움직임
5. 센서 노이즈 및 동적 장애물에 대한 강인성

## 2. 개발 원칙

### 2.1 기존 시스템 보존

기존에 정상적으로 작동하는 기능을 불필요하게 변경하지 않는다.

기존 NMPC 기반 GoToPose를 비교 기준으로 보존한다.

개발 전 현재 코드의 Git 상태, 설정값, 동역학 모델 및 기존 테스트 결과를 기록한다.

수정되지 않은 기존 버전을 재현할 수 있도록 Git 브랜치, 태그 또는 이에 준하는 기준점을 확보한다.

신규 제어 방식을 도입하기 위해 기존 Behavior Tree, Skill 및 ROS 2 인터페이스를 전면 재설계하지 않는다.

### 2.2 하나의 GoToPose 인터페이스 유지

여러 개의 독립적인 GoToPose Skill을 중복 개발하지 않는다.

기존 GoToPose 내부에서 경로 생성기 및 제어기 Backend를 선택할 수 있는 구조로 확장한다.

기존 BT XML과 GoToPose 사용법은 최대한 유지한다.

제어기 및 회피 옵션을 명시적으로 변경하지 않으면 기존 동작을 유지해야 한다.

### 2.3 실제 센싱 기반 제어

실제 로봇과 시뮬레이션에서 다음 정보를 사용한다.

- LiDAR 기반 Localization
- IMU
- Wheel Odometry
- 카메라 기반 공 위치 추정
- LiDAR 기반 상대 로봇 위치 및 속도 추정
- 기존 World Model

시뮬레이션 Ground Truth를 경로 생성, 장애물 회피, 성공 판정 및 제어 입력 계산에 직접 사용하지 않는다.

Ground Truth는 성능 평가에만 사용한다.

### 2.4 실측 기반 개발

기존에 식별한 Pinky의 물리 및 동역학 파라미터를 최대한 재사용한다.

- 좌우 바퀴 유효 반경
- 축간거리
- 최대 바퀴 회전속도
- 최대 선속도 및 각속도
- 가속 및 감속 특성
- 모터 응답 지연
- 모터 시정수
- 모터 데드존
- 기존 동역학 보정 YAML
- 기존 NMPC 동역학 모델

기존 파라미터가 실제 제어기에 적용되고 있는지 확인한다.

이미 수행한 캘리브레이션을 특별한 근거 없이 다시 진행하거나 덮어쓰지 않는다.

### 2.5 경량성 우선

복잡한 알고리즘을 도입하는 것 자체를 목표로 하지 않는다.

단순한 기하학적 연산, 대수 연산 및 소규모 탐색으로 충분한 성능을 확보할 수 있다면 이를 우선한다.

새로운 외부 라이브러리나 패키지 추가를 최소화한다.

## 3. 기존 코드 및 제어 구조 분석

신규 제어기를 개발하기 전에 현재 GoToPose 및 NMPC 구현을 충분히 분석한다.

다음 사항을 확인한다.

- GoToPose 실행 및 종료 구조
- Behavior Tree Tick 주기
- NMPC 실행 주기
- acados Solver 설정
- 예측 구간 및 Shooting Node 수
- 기존 동역학 모델과 상태 변수
- 위치 및 자세 비용함수
- 입력 변화량 비용함수
- 장애물 회피 제약조건
- Solver Warm Start 방식
- Solver 실패 시 처리
- `/cmd_vel` 발행 주기
- 모터 제어 및 피드백 주기
- Watchdog 동작 조건
- Localization 및 TF 갱신 구조
- 성공 및 실패 판정 조건
- 행동 종료 시 정지 명령 발행 여부

이전 개발 과정에서 9상태 모델, 실측 동역학 보정, 입력 변화량 제약, 예측 구간 변경 및 acados 기반 최적화가 논의되거나 적용되었다.

다만 현재 코드에 실제로 어떤 기능이 적용되어 있는지는 소스코드를 기준으로 다시 확인한다.

이전 대화에서 언급된 제어 주기와 Solver 연산 시간을 확정된 최신 상태로 가정하지 않는다.

## 4. 실물 주행 버벅임 원인 분석

현재 발생하는 버벅임의 원인을 NMPC 연산량 문제라고 단정하지 않는다.

- 유효 제어 입력 누락
- 새로운 명령이 들어오기 전까지 기존 명령을 유지하지 못하는 문제
- 불필요한 0 속도 명령 삽입
- Watchdog 개입
- ROS 2 통신 지연
- Localization 위치 및 자세 추정값 급변
- 모터 데드존
- 실제 모터 응답 지연
- 속도 및 가속도 제약의 불일치
- 과도한 제어 게인
- Behavior Tree에서의 반복적인 Goal 갱신
- 복수 노드의 속도 명령 발행
- 전체 시스템 동시 실행에 따른 CPU 부하

다음 데이터를 동일한 시간축으로 기록할 수 있도록 한다.

- 목표 Pose
- 추정 Pose
- 참조 선속도 및 각속도
- NMPC 계산 결과
- Solver 상태 및 연산 시간
- 최종 `/cmd_vel`
- 실제 좌우 바퀴 속도
- 실제 선속도 및 각속도 추정값
- Localization 보정량
- Watchdog 상태
- Behavior Tree 상태
- GoToPose 종료 상태
- 각 노드의 처리 시간 및 갱신 주기

속도 명령이 불연속적인 것인지, 속도 명령은 정상인데 실제 로봇의 응답이 불연속적인 것인지 반드시 구분한다.

## 5. 기본 이동 기능 우선 검증

장애물이 없는 상황에서 다음 시험을 먼저 수행한다.

1. 고정 속도 명령을 이용한 직선 주행
2. 고정 각속도 명령을 이용한 제자리 회전
3. 가속 및 감속 주행
4. 직선 GoToPose
5. 곡선 GoToPose
6. 다양한 초기 방위각에서 목표점 이동
7. 전진 및 후진 이동
8. 가까운 목표점 이동
9. 목표 위치는 동일하고 자세만 다른 경우
10. 연속적인 GoToPose 수행

이 단계에서는 장애물 회피 알고리즘의 복잡도를 추가하지 않는다.

기본 이동 자체가 부드럽고 정확하게 수행되지 않는다면 장애물 회피 기능을 추가하기 전에 문제를 우선 해결한다.

## 6. 제어 입력 연속성 및 실시간성 확보

제어 명령은 단일 관리 체계에서 전달한다.

정상적인 제어 입력이 생성되지 않는 순간마다 무조건 0 속도를 발행하는 구조가 있는지 확인한다.

이전에 계산한 유효한 제어 입력 또는 예측 입력을 제한된 시간 동안 사용할 수 있는지 검토한다.

다만 기존 입력을 무조건 유지하는 것도 위험할 수 있으므로 다음 조건을 확인한다.

- 명령의 유효 시간
- 센서 데이터 최신성
- 현재 충돌 위험
- 기존 참조 궤적의 유효성
- 로봇의 현재 상태
- Watchdog 및 통신 상태

유효한 입력을 사용할 수 없는 경우에는 안전하게 감속하거나 정지한다.

Watchdog을 비활성화하거나 무조건적인 명령 유지 방식으로 버벅임을 숨기지 않는다.

Solver 실패, 제어 주기 초과 및 입력 누락의 근본 원인을 기록하고 해결한다.

# PART B. 모든 위치 제어기가 만족해야 하는 세 가지 핵심 요구사항

## 7. 핵심 요구사항 1 — 센서 노이즈에 강인한 위치 제어

Pinky의 위치와 자세는 Ground Truth가 아닌 센싱 및 상태 추정 결과에 의존한다.

따라서 실제 로봇이 동일한 위치에 있더라도 추정 위치가 흔들릴 수 있다.

이러한 추정 오차를 모두 실제 위치 오차로 판단하여 제어하면 로봇이 불필요하게 앞뒤로 움직이거나 좌우로 회전할 수 있다.

### 7.1 상태 추정 연속성

현재 Localization, IMU 및 Wheel Odometry의 사용 구조를 확인한다.

다음 원칙을 활용한다.

- LiDAR: 경기장 기준 절대 위치 보정
- Wheel Odometry: 단시간 동안 연속적인 이동 추정
- IMU: 연속적인 방위각 및 회전 추정

필요한 경우 기존 상태 추정기의 필터링, 이상치 제거 및 보정량 처리 방식을 개선한다.

기존에 구현된 Localization 알고리즘을 불필요하게 교체하지 않는다.

`map`, `odom`, `base_link` 좌표계의 관계를 활용하여 절대 위치 보정이 제어 입력의 급격한 변화로 이어지지 않도록 한다.

단, 전역 위치 보정과 로컬 참조 궤적 변환을 일관되게 관리하여 절대 위치 오차가 영구적으로 남지 않도록 한다.

### 7.2 제어 입력의 노이즈 민감도

다음 사항을 검토한다.

- 위치 및 자세 오차에 대한 제어 게인
- 센서 노이즈에 따른 제어 입력 변동
- 불필요한 저속 보정
- 고주파 추정 오차의 증폭
- 모터 데드존 및 입력 포화
- 측정값의 시간 지연
- 상태 추정 불확실성

필터링을 지나치게 강하게 적용하여 실제 움직임 또는 갑작스러운 장애물에 대한 반응까지 느려지지 않도록 한다.

### 7.3 경로 생성의 노이즈 민감도

자기 위치, 공 위치, 상대 로봇 위치가 조금씩 변경된다는 이유만으로 매번 경로를 다시 생성하지 않는다.

기존 경로가 여전히 안전하고 목표 달성이 가능하다면 이를 유지한다.

다음 방식을 검토한다.

- Event-Triggered Replanning
- Replanning Hysteresis
- 목표 위치 변경 임계값
- 장애물 위치 불확실성 기반 안전 여유
- 경로 변경 비용
- 기존 회피 방향 유지

상대 위치는 LiDAR 군집 평균점이므로 실제 기하학적 중심과 다를 수 있다는 점도 고려한다.

작은 센서 노이즈에는 둔감하고 실제 환경 변화에는 민감하게 반응하는 구조를 구현한다.

## 8. 핵심 요구사항 2 — 정밀성을 유지하는 빠른 행동 전환

현재 목표점 도달 조건이 엄격하면 목표점 부근에서 반복적인 전후진과 방향 보정이 발생할 수 있다.

또한 위치, 자세, 속도 및 유지 시간 조건을 모두 만족하기까지 불필요하게 긴 시간이 발생할 수 있다.

로봇 축구에서는 모든 행동을 주차하듯 완벽하게 종료한 뒤 다음 행동을 시작할 필요가 없다.

### 8.1 제어 목표와 행동 완료 조건 분리

제어기의 목표 정밀도는 기존과 동일하게 유지한다.

제어기는 이동하는 동안 최대한 정확하게 목표 위치와 자세를 추종해야 한다.

다만 행동 완료 조건은 단순한 목표점 오차뿐 아니라 다음 행동의 실행 가능성을 고려하도록 한다.

모든 성공 허용 오차를 일괄적으로 완화하는 방식으로 문제를 해결하지 않는다.

### 8.2 현재 상태 기반 다음 행동 계획

이전 행동의 목표점에 약간의 오차가 남아 있더라도 다음 행동을 정상적으로 수행할 수 있다면, 해당 오차를 제거하기 위해 다시 이전 목표점으로 이동하지 않는다.

행동 완료 시점의 실제 추정 상태를 다음 행동에 전달한다.

전달할 정보는 다음과 같다.

- 현재 추정 위치 x, y
- 현재 추정 방위각 yaw
- 현재 선속도 v
- 현재 각속도 omega
- 필요한 경우 가속도
- 상태 타임스탬프
- 상태 추정 신뢰도
- 이전 목표 대비 위치 및 자세 오차
- 행동 종료 사유

다음 행동은 이전 행동의 이상적인 목표 Pose가 아니라 최신 실제 추정 상태를 초기조건으로 사용한다.

즉, 목표 A에 정확하게 도달하지 못했더라도 현재 상태에서 목표 B 또는 다음 Skill을 정상적으로 수행할 수 있다면 목표 A의 잔여 오차를 다시 보정하지 않는다.

다음 행동에서 새로운 궤적을 계획하면서 잔여 오차를 자연스럽게 처리한다.

기존 World Model 또는 ROS 2 메시지로 해당 정보를 제공할 수 있다면 불필요한 중복 메시지를 생성하지 않는다.

### 8.3 행동별 완료 판정

다음 완료 모드를 검토한다.

#### LEGACY

기존 GoToPose의 성공 및 종료 조건을 그대로 사용한다.

기존 방식과의 비교를 위한 기준 모드이다.

#### STRICT_STOP

정밀한 목표 위치 및 자세에 도달하고 정지한 이후 완료한다.

경기 시작 위치 이동, 캘리브레이션 등 실제 정지가 필요한 상황에 사용한다.

#### PRACTICAL_STOP

다음 작업에 필요한 위치 및 자세 조건을 만족하는 범위에서 정지하고 완료한다.

목표점 주변의 불필요한 미세 위치 보정을 최소화한다.

#### PASS_THROUGH

중간 경유점을 통과하는 경우에 사용한다.

목표점 통과 방향, 횡방향 오차, 자세 및 안전한 후속 경로의 존재 여부를 검사한다.

조건을 만족하면 불필요하게 정지하지 않고 다음 행동으로 연결한다.

#### HANDOFF

다음 행동의 실행 가능 조건을 만족하면 현재 상태를 전달하고 제어권을 넘긴다.

예를 들어 공 뒤쪽의 이상적인 목표점에 정확히 도달하지 않았더라도 현재 로봇과 공의 위치 관계가 드리블 또는 슛을 수행하기에 충분하다면 즉시 다음 행동으로 전환한다.

### 8.4 다음 행동 실행 가능성

다음 행동마다 필요한 상태 조건이 다르다는 점을 고려한다.

- 일반 이동: 안전한 다음 이동 경로 생성 가능 여부
- 공 접근: 공에 접근할 수 있는 위치와 방향
- 드리블: 공과 범퍼 사이의 상대 위치 및 속도
- 슛: 공과 상대 골대 사이의 정렬 상태
- 수비: 실제 공격 경로를 차단할 수 있는 상태
- 경기 준비: 지정된 시작 위치 및 자세에서 정지

GoToPose가 경기 전략을 직접 결정하는 구조로 만들지 않는다.

행동별 완료 조건은 기존 BT 또는 Skill의 요구사항을 통해 전달할 수 있도록 설계한다.

### 8.5 수렴 정체 및 반복 보정 감지

다음 현상을 감지할 수 있도록 한다.

- 일정 시간 동안 목표 오차가 유의미하게 감소하지 않음
- 목표점 주변의 반복적인 전진 및 후진
- 좌우 각속도의 불필요한 부호 변경
- 모터 데드존에 따른 미세 보정 실패
- 센서 노이즈 수준보다 작은 오차의 반복 보정

현재 상태에서 다음 행동이 가능하다면 불필요한 재수렴을 중단하고 다음 행동으로 전환한다.

다음 행동을 수행할 수 없다면 새로운 접근 경로를 생성하거나 실패를 반환한다.

시간이 오래 걸렸다는 이유만으로 임의로 SUCCESS를 반환하지 않는다.

### 8.6 행동 전환 시 제어 명령 연속성

기존 Skill의 종료 함수, BT halt 처리 및 Action 완료 처리에서 무조건 0 속도를 발행하는 부분이 있는지 확인한다.

PASS_THROUGH 또는 HANDOFF에서 정상적인 제어권 전환이 가능하다면 불필요한 정지 명령을 제거한다.

단, 다음 행동의 제어 명령이 실제로 준비되었는지 확인해야 한다.

이전 행동과 다음 행동이 동시에 모터 명령을 발행하지 않도록 한다.

다음 행동이 준비되지 않았거나 제어권 전환에 실패하면 안전하게 감속 또는 정지한다.

목표는 개별 행동의 완료 시간이 아니라 전체 경기 행동의 연속성과 수행 시간을 개선하는 것이다.

## 9. 핵심 요구사항 3 — 실시간 장애물 회피와 연속적인 궤적 전환

Pinky는 빠르게 움직이면서 벽, 상대 로봇 및 공을 필요에 따라 회피할 수 있어야 한다.

동시에 장애물 위치가 변경되거나 새로운 경로가 생성되었을 때 로봇이 갑작스럽게 방향을 바꾸거나 불필요하게 감속하지 않아야 한다.

### 9.1 회피 옵션 유지

기존 GoToPose에서 제공하는 벽, 상대 및 공 회피 옵션을 유지한다.

회피 옵션을 활성화하지 않은 경우 불필요하게 회피 연산을 수행하지 않는다.

공을 밀거나 슛하는 등 의도적인 접촉이 필요한 행동과 일반적인 장애물 회피를 구분한다.

전략적 회피 옵션과 하드웨어 안전 보호 조건을 혼동하지 않는다.

### 9.2 이벤트 기반 재계획

다음 상황에서 새로운 경로 생성 여부를 판단한다.

- 기존 경로에 실제 충돌 위험 발생
- 목표 위치의 유의미한 변화
- 상대 로봇의 이동으로 기존 경로 무효화
- 자기 위치 추정의 큰 보정
- 기존 경로에서 허용 범위를 벗어난 추종 오차
- 예상 도착 시간의 유의미한 개선

작은 관측 변화만으로 경로를 반복해서 재생성하지 않는다.

기존 경로가 안전한 경우에는 기존 경로를 우선 유지한다.

### 9.3 회피 방향의 일관성

상대 로봇 왼쪽과 오른쪽의 회피 경로가 비슷한 성능을 가지는 경우, 작은 센서 노이즈로 회피 방향이 반복적으로 변경되지 않도록 한다.

기존 경로와 신규 경로의 예상 남은 도착 시간, 안전성, 전환 비용을 함께 평가한다.

예시 비용함수:

J = T_arrival + lambda_path × J_path_change + lambda_input × J_input_change

기존 경로가 안전하다면 작은 시간 단축만을 위해 경로를 변경하지 않는다.

단, 실제 충돌 위험이 발생한 경우에는 경로 변경 비용이나 최소 유지 시간보다 안전성을 우선한다.

### 9.4 Trajectory Splicing

새로운 경로가 생성되더라도 기존 경로를 즉시 삭제하고 완전히 다른 경로를 입력하지 않는다.

기존 궤적과 새로운 궤적을 가능한 한 부드럽게 연결한다.

다음 연속성을 고려한다.

- 위치 연속성
- 방위각 연속성
- 선속도 연속성
- 각속도 연속성
- 곡률 연속성
- 선가속도 및 각가속도 연속성

Bézier Curve, Clothoid, Quintic Polynomial 등 적절한 경로 연결 기법을 검토한다.

현재 제어 입력과 로봇의 실제 상태를 고려한다.

경로 생성에 소요되는 시간까지 고려하여 실제 궤적 전환 시점의 예상 상태를 초기조건으로 사용할 수 있도록 한다.

연결된 궤적이 차동구동 비홀로노믹 제약, 충돌 조건 및 구동기 제약을 만족하는지 반드시 다시 검사한다.

경로를 단순히 보간했다는 이유만으로 주행 가능한 궤적이라고 가정하지 않는다.

### 9.5 Active/Pending Trajectory Buffer

다음 두 개의 궤적을 관리하는 방식을 검토한다.

- Active Trajectory: 현재 제어기가 추종 중인 유효한 궤적
- Pending Trajectory: 새롭게 생성하거나 검증 중인 궤적

새로운 경로를 계산하는 동안 기존 경로가 안전하다면 계속 추종한다.

새로운 경로의 안전성과 연속성이 확인되었을 때만 제어기에 전달한다.

경로 생성 작업 때문에 제어 루프가 블로킹되지 않도록 한다.

오래된 목표나 센서 데이터로 생성된 Pending Trajectory가 뒤늦게 적용되지 않도록 타임스탬프 및 버전 관리를 수행한다.

### 9.6 독립적인 Collision Monitor

일반적인 경로 계획과 긴급 충돌 대응을 분리한다.

World Model의 필터링된 객체 정보뿐 아니라 필요한 경우 원본 LiDAR 및 초음파 데이터를 활용하여 실제 충돌 위험을 판단한다.

상대 로봇 추적기가 아직 상대를 확정하지 않았더라도 실제 장애물에 대응할 수 있어야 한다.

기본 제동거리 모델은 다음과 같다.

d_stop = v × tau + v² / (2 × a_dec) + d_margin

여기서 tau는 센서, 연산, 통신 및 모터 응답 지연을 포함한다.

동적 장애물의 접근 속도, 회전 주행 시 로봇의 swept footprint 및 위치 추정 불확실성도 고려한다.

다음과 같이 대응한다.

- 기존 경로가 안전함: 정상 추종
- 미래 충돌 가능성 발생: 재계획 요청
- 제동거리가 부족해질 가능성: 속도 제한 및 감속
- 충돌 임박: 즉시 안전 정지

긴급 대응은 일반적인 경로 안정화 필터나 히스테리시스로 인해 지연되지 않아야 한다.

안전성을 확보할 수 없는 상황에서는 최고속도 유지보다 충돌 방지를 우선한다.

# PART C. 기존 NMPC 개선

## 10. 기존 NMPC 개선 방향

현재 NMPC의 기본 구조는 유지하면서 장애물 회피 경로 생성 성능과 Solver 안정성을 개선한다.

다음 사항을 우선 검토한다.

- 비용함수의 위치·자세 오차 가중치
- 불필요한 회전 및 후진을 유발하는 비용 구조
- 입력 변화량 및 가감속 제약
- 장애물 회피 제약의 구성
- 초기해의 품질
- 이전 최적해의 재사용
- Solver 실패 복구
- 예측 경로의 시간적 일관성
- 참조 경로 또는 목표점 갱신 방식

장애물 회피 제약 때문에 Solver가 좌우 회피 방향을 찾지 못하거나 비효율적인 국소해에 빠지는 현상을 분석한다.

## 11. 경량 함수 기반 경로 변형

기존 경로 전체를 다시 생성하는 대신 장애물이 존재하는 구간만 기하학적으로 변형하는 방법을 개발한다.

기본 개념은 다음과 같다.

p_new(s) = p_base(s) + f(s) × n(s)

- p_base(s): 기존 기본 경로
- f(s): 장애물 회피를 위한 변위 함수
- n(s): 기존 경로에 수직인 단위벡터

회피 함수는 유한한 구간에서만 작동하는 Bump Function을 우선 검토한다.

예시:

f(s) = A × cos⁴[π(s − s_o)/(2L)]

단, |s − s_o| ≤ L인 구간에서만 적용하고 나머지 구간에서는 0으로 정의한다.

- A: 최대 회피 변위
- s_o: 장애물의 경로상 위치
- L: 회피 시작 및 종료 범위

회피 시작점과 종료점에서 위치, 진행 방향 및 곡률의 연속성을 확보할 수 있도록 한다.

Gaussian, 접선 및 원호 기반 변형도 비교할 수 있다.

복잡한 전체 경로 최적화보다는 소수의 회피 함수 파라미터를 탐색하는 경량 구조를 우선한다.

### 11.1 장애물 확장

장애물의 실제 외곽선만 따라가는 경로를 생성하지 않는다.

다음 항목을 고려하여 장애물 회피 영역을 설정한다.

- 자기 로봇 외곽 크기
- 상대 로봇 또는 공의 크기
- 위치 추정 불확실성
- 관측 대표점과 실제 물체 중심의 차이
- 추종 오차
- 추가 안전 여유

경로 변형 이후 벽과 다른 장애물과의 충돌도 다시 검사한다.

### 11.2 회피 방향 및 회피 폭 선택

다음 후보를 비교한다.

- 좌측 회피
- 우측 회피
- 다양한 회피 폭
- 다양한 회피 시작 거리
- 다양한 회피 종료 거리

단순히 이동 거리가 가장 짧은 경로를 선택하지 않는다.

곡률에 따른 주행 가능 속도와 가감속 조건을 고려하여 예상 도착 시간이 가장 짧은 후보를 선택한다.

함수 기반 변형만으로 안전한 경로를 생성할 수 없는 경우 다른 기하학적 경로 생성 방법 또는 전체 재계획으로 전환한다.

## 12. NMPC Warm Start 개선

기존 NMPC의 이전 예측 경로 또는 기본 경로에 장애물 회피 함수를 적용하여 Solver 초기해로 제공하는 방식을 개발한다.

단순히 x, y 위치만 변경하여 초기해로 전달하지 않는다.

변형된 경로에 대응하는 다음 정보를 일관되게 구성한다.

- 위치
- 방위각
- 선속도
- 각속도
- 필요한 동역학 상태
- 제어 입력

기존 NMPC의 동역학 및 장애물 제약조건은 가능한 한 유지한다.

기존 방식과 비교하여 다음 개선 여부를 검증한다.

- Solver 수렴률
- Solver 반복 횟수
- 연산 시간
- 장애물 회피 성공률
- 회피 경로 품질
- 입력 연속성
- 실제 도착 시간

Warm Start 개선이 실제로 연산량을 줄이는지는 실험으로 판단한다.

## 13. Tracking NMPC 추가

기존 통합 NMPC와 별도로 외부 궤적 생성기가 제공하는 참조 궤적을 추종하는 Tracking NMPC 방식을 검토한다.

외부 궤적 생성기에서 다음 정보를 제공한다.

- x_ref(t)
- y_ref(t)
- yaw_ref(t)
- v_ref(t)
- omega_ref(t)
- 필요한 경우 가속도 및 Feedforward 입력

Tracking NMPC는 회피 경로를 처음부터 탐색하기보다는 제공된 궤적을 정확하게 추종하는 역할을 수행한다.

필요한 장애물 및 동역학 제약조건은 유지한다.

기존 NMPC의 출력 경로만 외부에서 변경하고 기존 제어 입력을 그대로 사용하는 잘못된 구조는 구현하지 않는다.

# PART D. 공통 경량 최소시간 궤적 생성기 개발

## 14. 개발 목적

Tracking NMPC, LTV-LQR 및 Block Backstepping에서 공통으로 사용할 수 있는 경량 궤적 생성기를 개발한다.

경로 생성과 속도 계획은 연계하되 실제 피드백 제어와는 분리한다.

목표는 최단거리 경로가 아니라 실제 로봇의 물리적 한계를 고려한 최소시간 궤적이다.

목적함수:

T = ∫ ds / |v(s)| + 제자리 회전 및 정지·전환에 필요한 시간

전체 가능한 궤적을 대상으로 전역 최단시간을 보장한다고 주장하지 않는다.

경량 후보 탐색을 통해 가능한 한 빠른 실행 가능한 궤적을 찾는 것을 우선 목표로 한다.

## 15. 경로 후보 생성

Pinky Soccer 경기장은 크기와 형상이 정해져 있고 주요 장애물 수가 제한적이다.

이를 활용하여 다음 경로 생성 기법을 우선 검토한다.

- 직선 경로
- 접선 및 원호 기반 경로
- Bézier Curve
- Clothoid
- Quintic Polynomial
- 함수 기반 국소 경로 변형
- 다양한 회피 폭 및 곡률을 가진 후보 경로

다음 초기조건 및 종단조건을 고려한다.

- 현재 추정 위치 및 자세
- 현재 선속도 및 각속도
- 목표 위치 및 자세
- 목표점 통과 또는 정지 여부
- 다음 행동에 필요한 속도
- 전진 및 후진 가능 여부

최단거리만을 기준으로 후보를 선택하지 않는다.

경로 길이가 조금 길더라도 높은 속도를 유지할 수 있다면 더 빠른 경로가 될 수 있다.

## 16. 차동구동 기반 최대속도 계획

Pinky의 운동학 모델은 다음과 같다.

x_dot = v cos(yaw)

y_dot = v sin(yaw)

yaw_dot = omega

경로 곡률을 kappa, 바퀴 반경을 r, 축간거리를 B라고 하면 전진 주행 시 다음 관계를 활용할 수 있다.

omega = v × kappa

wheel_R = v(1 + B × kappa/2) / r

wheel_L = v(1 − B × kappa/2) / r

이를 이용하여 경로상의 각 위치에서 실제 바퀴 구동 한계를 만족하는 최대 허용 속도를 계산한다.

다음 제약조건을 적용한다.

- 최대 선속도
- 최대 각속도
- 좌우 바퀴 최대 회전속도
- 최대 전진 및 후진 속도
- 최대 가속도 및 감속도
- 최대 각가속도
- 바퀴 가속도
- 모터 응답 특성
- 곡률에 따른 주행 한계
- 필요한 경우 횡가속도 및 Jerk
- 시작 및 종료 속도
- 실제 피드백 제어에 필요한 입력 보정 여유

Pinky가 불필요하게 느린 속도로 작동하지 않도록 한다.

실제 물리적 한계와 안전성 범위에서 가능한 한 최고속도에 가까운 속도 프로파일을 생성한다.

## 17. 최소시간 속도 프로파일 생성

초기에는 Forward-Backward Pass를 우선 적용한다.

가속 조건:

v_next² ≤ v_current² + 2 × a_acc × ds

감속 조건:

v_current² ≤ v_next² + 2 × a_dec × ds

각 경로 위치에서 허용 가능한 속도 상한과 가속 및 감속 제약을 종합하여 속도 프로파일을 생성한다.

현재 로봇이 이미 이동 중인 경우 초기 속도를 무조건 0으로 설정하지 않는다.

PASS_THROUGH 또는 HANDOFF 조건에서는 필요한 경우 종료 속도를 0보다 크게 설정한다.

단순 Forward-Backward Pass로 바퀴 가속도, 각가속도 및 기타 결합 제약을 충분히 처리할 수 없는 경우 TOPP-RA 또는 이에 준하는 경량 속도 계획 방법을 검토한다.

### 17.1 경로별 예상 도착 시간

각 후보 경로에 대해 속도 프로파일을 생성한 후 실제 주행에 필요한 시간을 계산한다.

다음 시간을 모두 포함한다.

- 초기 방향 정렬
- 가속
- 직선 주행
- 곡선 주행
- 장애물 회피
- 감속
- 필요한 최종 자세 정렬
- 필요한 정지 및 방향 전환

가장 짧은 시간에 목표 행동을 완료할 수 있는 유효한 후보를 선택한다.

후보 경로 생성, 속도 계획 및 평가의 최대 계산량을 제한하여 실시간성을 확보한다.

## 18. 동적 장애물 고려

상대 로봇의 추정 위치 및 속도를 이용하여 단기 미래 위치를 예측한다.

초기에는 등속도 모델을 우선 활용한다.

p_opp(t) = p_opp(0) + v_opp × t

상대 속도를 정확하게 추정할 수 없는 경우에는 신뢰도에 따른 보수적인 장애물 범위를 사용한다.

동적 장애물은 공간상의 위치뿐 아니라 우리 로봇이 해당 위치를 통과하는 시간까지 고려하여 충돌 여부를 판단한다.

필요에 따라 다음 대응을 검토한다.

- 좌우 회피
- 회피 폭 변경
- 통과 시간 조정
- 일시적인 감속
- 안전한 경우 기존 경로 유지
- 긴급 재계획

과도하게 긴 미래 예측에 의존하지 않는다.

# PART E. 신규 LTV-LQR 제어기

## 19. 개발 목적

공통 최소시간 궤적 생성기의 결과를 추종하는 경량 LTV-LQR 제어기를 개발한다.

매 제어 주기마다 비선형 최적화 문제를 해결하지 않고 높은 주파수로 위치, 자세 및 속도 오차를 보정하는 것을 목표로 한다.

## 20. 제어기 설계

Pinky의 차동구동 운동학 및 기존 실측 동역학 모델을 확인한다.

참조 궤적을 기준으로 모델을 선형화한다.

오차 동역학:

delta_x_dot = A(t) × delta_x + B(t) × delta_u

제어 입력:

u = u_ref − K(t) × delta_x

Feedforward 입력과 LQR 피드백을 결합한다.

가능하면 궤적 생성 단계에서 LQR 게인을 계산하여 제어 루프에서는 간단한 상태 오차 계산 및 행렬 연산만 수행하도록 한다.

이산시간 LQR, 유한 시간 Riccati Recursion 또는 적절한 Gain Scheduling을 검토한다.

상태 추정 노이즈를 과도하게 증폭하지 않도록 Q, R 및 필요 시 입력 변화량 관련 설계를 검토한다.

입력 포화가 발생하더라도 실제 바퀴 속도와 가감속 한계를 위반하지 않도록 한다.

## 21. 저속 및 종단 상태 처리

차동구동 시스템은 정지 상태 부근에서 일반적인 선형화 기반 제어만으로 모든 Pose 오차를 안정적으로 제거하기 어려울 수 있다.

다음 상황을 구분한다.

- 정상적인 이동 궤적 추종
- 저속 주행
- 후진
- 제자리 회전
- 최종 정지
- 다음 행동으로 연속 전환

필요한 경우 경량 Hybrid 종단 제어를 사용한다.

정지 상태에서의 횡방향 오차 때문에 반복적인 미세 이동이 발생하지 않도록 공통 행동 완료 및 전환 관리자와 연동한다.

# PART F. 신규 Block Backstepping 제어기

## 22. 개발 목적

Pinky는 세 개의 평면 Pose 상태 x, y, yaw를 두 개의 독립적인 입력 v, omega 또는 좌우 바퀴 입력을 통해 제어하는 차동구동 시스템이다.

직접적인 횡방향 구동이 불가능한 비홀로노믹 제약을 가진다.

이러한 구조를 활용하여 Lyapunov 기반의 비선형 Backstepping 제어기를 추가한다.

LTV-LQR과 동일한 공통 참조 궤적을 사용하도록 하여 순수 추종 제어기의 성능을 비교할 수 있게 한다.

## 23. 비선형 운동학 제어 블록

참조 궤적과 실제 로봇의 오차를 로봇 Body Frame에서 정의한다.

e_x = cos(yaw)(x_ref − x) + sin(yaw)(y_ref − y)

e_y = −sin(yaw)(x_ref − x) + cos(yaw)(y_ref − y)

e_yaw = wrap(yaw_ref − yaw)

오차 동역학은 다음과 같다.

e_x_dot = omega × e_y − v + v_ref cos(e_yaw)

e_y_dot = −omega × e_x + v_ref sin(e_yaw)

e_yaw_dot = omega_ref − omega

초기 비교 제어기로 다음과 같은 Lyapunov 기반 비선형 운동학 제어식을 검토한다.

v_c = v_ref cos(e_yaw) + k_x × e_x

omega_c = omega_ref + k_y × v_ref × e_y + k_yaw × sin(e_yaw)

Lyapunov 후보함수:

V_1 = 0.5(e_x² + e_y²) + (1 − cos(e_yaw))/k_y

이상적인 운동학 모델과 양의 제어 게인에 대해 다음 관계를 확인한다.

V_1_dot = −k_x × e_x² − (k_yaw/k_y) × sin²(e_yaw)

단, V_1_dot가 음의 준정부호라는 사실만으로 모든 상태의 전역 점근 안정성이 자동으로 보장되는 것은 아니다.

참조 궤적 조건, 불변집합 및 정지 상태에서의 안정화 한계를 별도로 분석한다.

이 운동학 제어기를 우선 검증하고 이후 동역학 기반 Block Backstepping으로 확장한다.

## 24. 동역학 기반 Block Backstepping

실제 Pinky의 모터 및 구동 동역학을 확인한다.

다음과 같은 계층 구조를 검토한다.

- 외부 블록: 위치 및 자세 오차 안정화
- 가상 제어 입력: 목표 선속도 및 각속도
- 내부 블록: 실제 선속도 및 각속도 또는 바퀴 속도 오차 안정화
- 최종 입력: 실제 Pinky에서 사용 가능한 속도 명령 또는 구동 입력

단순화된 구동 모델 예시:

v_dot = (v_cmd − v)/tau_v + d_v

omega_dot = (omega_cmd − omega)/tau_omega + d_omega

실제 식별된 모델과 적합하지 않다면 위 모델을 강제로 적용하지 않는다.

내부 오차:

z_2 = [v − v_c, omega − omega_c]ᵀ

확장 Lyapunov 함수:

V_2 = V_1 + 0.5 × z_2ᵀ × P × z_2

외부 블록과 내부 블록 사이의 결합항을 포함하여 제어입력을 설계한다.

단순히 외부 운동학 제어기와 내부 PID를 연결한 것을 완성된 Block Backstepping이라고 정의하지 않는다.

실제 Block Backstepping 구조에 대한 오차 동역학 및 안정성 분석을 수행한다.

제어식 유도, 가정, 제어 게인 및 적용 범위를 별도로 문서화한다.

## 25. 실제 입력 인터페이스 고려

Pinky가 `/cmd_vel` 기반으로 내부 모터 제어기를 사용한다면 직접적인 토크 제어가 가능하다고 가정하지 않는다.

내부 모터 제어기를 포함한 실제 입출력 모델에 맞추어 Backstepping 제어기를 설계한다.

가상 입력의 시간 미분이 필요한 경우 센서 측정값을 단순 수치 미분하여 노이즈를 증폭시키지 않는다.

해석적인 참조 미분, 적절한 필터 또는 Command-Filtered Backstepping을 필요한 범위에서 검토한다.

## 26. 비홀로노믹 시스템의 안정화 한계

정지 목표 Pose에 대한 매끄러운 시불변 상태 피드백의 안정화 한계를 고려한다.

다음 상황을 구분하여 설계한다.

- 이동 중 궤적 추종
- 저속 추종
- 제자리 회전
- 최종 정지 자세 제어
- 후진
- 다음 행동으로의 연속 전환

필요한 경우 Hybrid 종단 제어를 사용한다.

센서 노이즈, 입력 포화, 모델 불확실성 및 구동기 지연이 포함된 실제 시스템에서의 안정성은 이상적인 Lyapunov 증명과 구분한다.

초기 개발에서는 NDOB 등 추가 외란관측기를 도입하지 않는다.

기본 운동학 및 동역학 Backstepping의 성능을 검증한 후 필요성이 확인된 경우에만 ISS 분석, 외란관측기 등을 확장한다.

# PART G. 다중 GoToPose Backend 구성

## 27. 비교할 제어 방식

다음 방식을 독립적으로 선택하고 비교할 수 있도록 구성한다.

### A. Legacy NMPC

개발 전 기존 GoToPose의 재현 가능한 비교 기준이다.

### B. Improved NMPC

기본 이동 문제, Solver 안정성 및 명령 연속성을 개선한 기존 통합 NMPC이다.

### C. Warm Start NMPC

기하학적 경로 변형을 통해 장애물 회피 초기해를 제공하는 NMPC이다.

### D. Tracking NMPC

공통 최소시간 궤적 생성기의 결과를 추종하는 NMPC이다.

### E. Time-Optimal LTV-LQR

공통 최소시간 궤적 생성기와 LTV-LQR 추종 제어기를 결합한다.

### F. Time-Optimal Block Backstepping

공통 최소시간 궤적 생성기와 비선형 Block Backstepping 제어기를 결합한다.

동역학 Backstepping 구현 이전에는 운동학 제어기를 별도의 내부 비교 기준으로 사용할 수 있다.

다만 운동학 제어기와 완성된 동역학 Backstepping의 결과를 구분하여 보고한다.

## 28. 공통 인터페이스

기존 GoToPose 내부에서 제어 방식을 선택할 수 있도록 한다.

다음은 설계 예시이며 실제 파라미터명과 인터페이스는 기존 코드에 맞추어 결정한다.

```yaml
GoToPose:
  controller: legacy_nmpc

  # legacy_nmpc
  # improved_nmpc
  # warm_start_nmpc
  # tracking_nmpc
  # time_optimal_lqr
  # time_optimal_backstepping

  completion_mode: legacy

  # legacy
  # strict_stop
  # practical_stop
  # pass_through
  # handoff

  avoid_walls: true
  avoid_opponent: true
  avoid_ball: false
```

제어기 선택과 행동 완료 모드는 독립적으로 설정할 수 있도록 한다.

동일한 완료 조건에서 여러 제어기를 비교할 수 있어야 한다.

회피 옵션이 비활성화된 경우 해당 회피 기능을 수행하지 않는다.

기존 BT XML에서 새로운 옵션을 지정하지 않았을 때 기존 동작이 유지되는지 회귀 테스트한다.

## 29. 실행 주기 및 병렬 처리

다음은 초기 검토 목표이다.

- LTV-LQR 및 Backstepping 피드백 제어: 50~100Hz
- Collision Monitor: 약 50Hz
- 속도 명령 발행: 기존 구조 활용, 50Hz 수준부터 검증
- 경로 재계획: 이벤트 기반, 최대 10~20Hz 수준부터 검증
- 기존 NMPC: 기존 설정 기준으로 측정
- Behavior Tree: 기존 주기 유지

위 주파수를 확정값으로 사용하지 않는다.

실제 센서 갱신률, CPU 성능, 통신 지연 및 전체 시스템 부하를 기준으로 설정한다.

경로 생성기가 제어 루프를 블로킹하지 않도록 적절한 비동기 실행 구조를 검토한다.

이전 계산이 완료되지 않은 상태에서 재계획 요청이 무한히 누적되지 않도록 한다.

실시간성이 확보되었다는 판단은 평균 처리 시간이 아니라 최악에 가까운 처리 시간, Deadline Miss, Jitter 및 명령 연속성을 기준으로 한다.

# PART H. 성능 비교 및 검증 환경 구축

## 30. 검증 목적

어떤 제어기가 가장 빠르고 정확하며 연산 부하가 적은지를 객관적으로 비교한다.

실험 결과를 보기 전에 특정 제어기를 최종 방식으로 선정하지 않는다.

## 31. 동일한 시험 조건

모든 제어 방식은 가능한 한 동일한 조건에서 비교한다.

- 동일한 경기장
- 동일한 로봇 모델
- 동일한 초기 위치 및 자세
- 동일한 초기 속도
- 동일한 목표 위치 및 자세
- 동일한 최대속도 및 가감속 한계
- 동일한 장애물 배치 및 이동 조건
- 동일한 센서 노이즈 및 지연 조건
- 동일한 회피 옵션
- 동일한 충돌 안전 여유
- 동일한 완료 판정 조건
- 동일한 하드웨어 및 실행 환경

전체 시스템 비교에서는 각 제어 방식이 자체적으로 가장 빠르다고 판단한 경로를 생성하도록 한다.

경로까지 강제로 동일하게 만들면 경로 생성기의 성능을 비교할 수 없기 때문이다.

순수 추종 제어기의 성능 비교에서는 Tracking NMPC, LTV-LQR 및 Block Backstepping에 동일한 참조 궤적을 제공한다.

이를 통해 전체 이동 시스템의 성능과 추종 제어기 자체의 성능을 각각 평가한다.

## 34. 센서 강인성 시험

- 정상 센서 데이터
- 자기 위치 추정 노이즈
- 자기 자세 추정 노이즈
- 상대 위치 추정 노이즈

## 35. 행동 전환 시험

개별 GoToPose뿐 아니라 여러 행동이 연결된 시나리오를 반드시 시험한다.

- 여러 경유점 연속 이동
- 공 뒤쪽 접근 후 드리블
- 공 접근 후 슛
- 공격 위치 이동 후 수비 위치 전환
- 이동 중 목표 변경
- 목표점 부근의 작은 잔여 위치 오차
- 목표점 부근의 작은 잔여 자세 오차
- 이전 행동의 목표점에 완전히 도달하지 않았지만 다음 행동이 가능한 경우
- 다음 행동이 아직 준비되지 않은 경우
- 다음 행동 전환 중 장애물 발생

정확한 이동 후 불필요한 정지, 재출발 및 와리가리 없이 자연스럽게 연결되는지 확인한다.

## 36. 완료 판정 개선 효과 분리

제어기 변경 효과와 행동 완료 조건 변경 효과를 혼동하지 않는다.

다음과 같은 비교를 수행한다.

- 동일 제어기 + 기존 완료 조건
- 동일 제어기 + 개선 완료 조건
- 서로 다른 제어기 + 동일 완료 조건
- 서로 다른 제어기 + 개선 완료 조건

필요하면 공통 경로 안정화 및 안전 관리 기능의 적용 전후도 별도로 비교한다.

모든 시험을 한꺼번에 진행하기 어렵다면 단계별 실험을 수행하되 중요한 비교 조건을 생략하지 않는다.

## 38. 반복 시험 및 최종 평가

동일한 시험을 여러 번 반복하여 평균뿐 아니라 결과 편차와 실패율을 기록한다.

성공한 시험 결과만으로 평균 이동 시간을 계산하여 실패율이 높은 제어기가 우수하게 평가되지 않도록 한다.

다음 원칙으로 평가한다.

1. 충돌 안전성 및 제어 안정성을 우선 확인한다.
2. 요구되는 위치 및 자세 정밀도를 만족하는지 확인한다.
3. 전체 행동 완료 시간과 행동 연결 성능을 비교한다.
4. 연산 부하와 실시간성을 비교한다.
5. 주행 부드러움 및 센서 노이즈 강인성을 비교한다.

최종적으로 단일 점수만 사용하기보다 속도, 정확성, 연산량 및 안정성 사이의 Pareto Trade-off를 분석한다.

모든 측면에서 우수한 방식이 존재하지 않는 경우 경기 상황에 따라 제어기를 선택할 수 있는 구조도 검토한다.

기존 버전의 성능 데이터를 먼저 기록한다.

## Phase 1. 기본 이동 문제 해결

장애물 없는 상태에서 발생하는 버벅임, 명령 누락, Solver 실패, 센서 추정 불안정 및 불필요한 목표점 보정을 분석한다.

기본 이동이 정상적으로 수행되도록 기존 제어 구조를 개선한다.

이 단계가 충분히 검증되기 전에는 복잡한 신규 제어기를 추가하지 않는다.

## Phase 2. 공통 제어 관리 기능 개발

다음 기능을 설계하고 단계적으로 검증한다.

- 상태 추정 연속성
- 공통 행동 완료 판정
- 실제 종료 상태 전달
- 행동 간 제어권 전환
- 명령 유효 시간 관리
- 입력 연속성 및 안전 관리

기존 동작과 개선 동작을 분리하여 검증할 수 있도록 한다.

## Phase 3. 기존 NMPC 장애물 회피 개선

기존 NMPC의 장애물 회피 문제를 재현한다.

함수 기반 경로 변형 및 Warm Start 개선을 개발한다.

기존 NMPC와 개선 NMPC의 성능을 비교한다.

## Phase 4. 공통 최소시간 궤적 생성기

기하학적 경로 후보 생성, 장애물 회피, 곡률 계산 및 최소시간 속도 계획을 구현한다.

경로 생성기의 정확성과 계산 시간을 독립적으로 검증한다.

## Phase 5. 경로 안정화 및 연속적인 재계획

다음 기능을 구현한다.

- 이벤트 기반 재계획
- 경로 유지 조건
- 회피 방향 히스테리시스
- Active/Pending Trajectory
- Trajectory Splicing
- 동적 장애물 예측
- 독립적인 충돌 감시

기존 경로에서 신규 경로로 전환하는 과정에 문제가 없는지 검증한다.

## Phase 6. Tracking NMPC

공통 최소시간 궤적 생성기를 기존 NMPC와 연결한다.

통합 NMPC와 Tracking NMPC를 비교한다.

## Phase 7. LTV-LQR

동일한 공통 참조 궤적을 사용하는 LTV-LQR 제어기를 개발한다.

추종 정확도, 최대속도 활용률 및 연산 시간을 검증한다.

## Phase 8. Block Backstepping

비선형 운동학 제어기를 우선 구현하고 검증한다.

이후 실측 구동 동역학을 포함한 Block Backstepping으로 확장한다.

제어식 유도와 안정성 분석을 수행한다.

동일한 궤적에서 LTV-LQR 및 Tracking NMPC와 비교한다.

## Phase 9. 전체 비교 시험

동일한 시험 환경에서 모든 제어 방식을 비교한다.

기본 이동, 장애물 회피, 센서 노이즈 및 연속 행동 시험을 수행한다.

## Phase 10. 실제 로봇 검증

MuJoCo 및 Gazebo에서 검증된 제어 방식을 실제 Pinky Pro에서 비교한다.

초기에는 제한된 속도에서 안전성을 검증하고 이후 단계적으로 실제 최대속도에 가까운 조건으로 확장한다.

실물에 접근할 수 없다면 실행 명령, 기록 방법 및 검증 절차를 제공한다.

실물 검증을 수행하지 않았음에도 검증 완료로 보고하지 않는다.

## Phase 11. 최종 제어 방식 결정

전체 비교 결과를 기반으로 다음 사항을 결정한다.

- 가장 빠른 이동 제어 방식
- 가장 정확한 이동 제어 방식
- 가장 연산량이 적은 제어 방식
- 가장 부드러운 이동 제어 방식
- 센서 노이즈에 가장 강인한 방식
- 실제 경기 적용에 가장 적합한 방식

기존 NMPC보다 신규 제어기가 반드시 우수해야 한다는 가정을 하지 않는다.

객관적인 결과를 통해 최종 제어기를 선정한다.

위 내용을 한 번에 무리하게 구현하지 않는다.

현재 기본 이동 문제를 재현하고 원인을 분석할 수 있는 시험 및 로깅 환경을 확보한다.

그 후 Phase 1의 기본 이동 개선부터 순차적으로 진행한다.

각 Phase마다 다음 내용을 기록한다.

- 개발 목표
- 기존 코드 분석
- 변경 사항
- 설계 근거
- 실행 방법
- 검증 결과

이미 정상적으로 구현된 기능은 중복 개발하지 않는다.

기존 시스템을 최대한 보존하면서 단계별로 검증 가능한 개발을 진행한다.

최종 목표는 복잡한 제어 알고리즘을 많이 구현하는 것이 아니라 실제 Pinky Pro가 빠르고 정확하며 가볍고 자연스럽게 움직이고, 장애물 및 센서 불확실성에도 안정적으로 대응하며, 여러 경기 행동을 불필요한 정지 없이 매끄럽게 수행하도록 만드는 것이다.
