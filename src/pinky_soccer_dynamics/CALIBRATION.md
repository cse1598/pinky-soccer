# 실물 Pinky Pro 구동 캘리브레이션 (2단계 절차 초안)

1단계(2026-11-23) 기준입니다. 실물 측정값은 아직 없습니다. 아래 순서대로 측정하고, 각 단계가 통과하면
다음 단계로 갑니다. 자동 주행은 사람이 옆에 있고 비상정지를 쥔 상태에서만 합니다.

## 0. 준비와 안전

- 장소: 장애물 없는 평평한 바닥(실제 경기 매트 위가 이상적), 바닥에 1 m 줄자와 테이프 기준선
- 로봇 받침대: 바퀴가 바닥에서 뜨도록 올려놓을 상자(바퀴 응답의 무부하 측정용)
- 비상정지: (a) 로봇 전원 스위치, (b) `ros2 topic pub --once /cmd_vel geometry_msgs/msg/Twist {}` 를 준비한 터미널,
  (c) 기존 command watchdog(0.5 s 명령 없으면 정지)
- 속도: 첫 실험은 0.05 m/s·0.3 rad/s 이하, 통과 후 단계적으로 올림
- 기록: 로봇 식별명(`robot_id`), 날짜(UTC), 바닥 재질, 배터리 전압을 실험마다 남김

## 1. 바퀴 부호 확인 (주행 없음)

`ros2 run pinky_soccer_dynamics check_wheel_signs` 실행 후 10초 안에 로봇을 손으로 약 20 cm 곧게 앞으로 민다.
결과 `measured_sign`이 `joint_sign` 설정과 같아야 한다. 코드 분석상 실물은 오른쪽 −1로 예상.

이 부호는 보정 UI의 바퀴 실험(`wheel_fit`)에도 영향을 줍니다. 보정 UI는 `/joint_states` 위치 차이를
그대로 쓰므로, 오른쪽이 반대 부호면 반경 추정이 범위 오류로 실패하거나 틀린 값이 나옵니다.
**바퀴 보정 전에 부호를 맞추는 결정이 필요합니다**(아래 "결정 필요" 참고).

## 2. 기하 보정: 유효 반경·바퀴 간격 (기존 보정 UI 재사용)

`pinky_soccer_calibration` 바퀴 탭(목표 odom 거리/각도 주행 + 범퍼 앞면 중앙 기준 실측 입력)을 사용.

| 실험 | 횟수 | 입력 | 얻는 값 |
|---|---|---|---|
| 전진 1 m | 3 | 종방향 m, 좌우 편향 mm | 평균 반경, 좌우 반경 차 |
| 후진 1 m | 3 | 동일 | 전후진 비대칭 |
| 좌회전 360° | 3 | 실제 누적 각도 | 바퀴 간격 |
| 우회전 360° | 3 | 동일 | 좌우 회전 비대칭 |

결과는 `results.wheels.left_radius_m / right_radius_m / separation_m`(+잔차·조건수·반복 통계)로
`profile.yaml`에 저장되고, `show_params --profile`이 `measured`로 반영합니다.
독립 검증: 다른 날 또는 다른 시작 위치에서 전진·회전 각 2회를 추가로 하고, 모델 예측 거리/각도와의
차이를 기록(목표: 거리 1 % 이내, 각도 2° 이내 — 시작 기준, 결과를 보고 조정).

## 3. 바퀴 응답: 시정수·지연·가속 한계 (새 도구 필요)

현재 보정 UI에는 계단 응답 실험이 없습니다. 2단계에서 다음 도구를 추가할 계획입니다(이 패키지,
실행 시 `--confirm-present` 필요, 기본 저속, 자동 정지, Bag/CSV로 `/cmd_vel`·`/joint_states`·`/odom` 기록).

1. **받침대 위(무부하)**: 바퀴 계단 명령 0 → ±2 → ±4 → ±6 rad/s, 각 0.8 s 유지, 좌우 동시·개별.
   측정: 지연(명령 후 첫 움직임), 시정수 τ, 경사(가속 한계). 공식 드라이버는 Profile Acceleration 200
   (약 74.9 rad/s²)을 설정하므로 1차 응답보다 경사형일 수 있음 → 두 모델을 모두 맞춰 비교.
2. **바닥 위(부하)**: 같은 계단을 0.05~0.15 m/s 범위에서, 직진·제자리 회전.
3. **명령 지연**: `/cmd_vel` 발행 시각과 `/joint_states` 속도 변화 시각의 차(시간 동기화 확인 후).
4. **최대 속도·가속도**: 드라이버 상한(100 rpm ≈ 10.47 rad/s)까지 단계적으로, 실제 도달값.
5. **추종 오차**: 정상상태 `Ω_meas/Ω_cmd`, 0.229 rpm 양자화 영향.

계산: `identification.fit_response`(지연·τ·가속 한계 격자 탐색) → 학습에 쓰지 않은 계단 세트로
`wheel_validation`(바퀴 속도 상대 RMS) → 전체 모델 `trajectory_validation`(0.5·1 s 개루프 위치/방향 오차).
통과 시에만 `accepted: true`인 식별 파일(`identification_schema: 1`)을 쓰고 `show_params --identification`으로 반영.

## 4. 반영과 검증 기록

- 실측 기록(원본 Bag/CSV, 실험 파일)과 채택 파라미터(profile.yaml, identification.yaml)를 분리 보관
- 각 값에 단위, 실험 UTC, robot_id, 검증 결과가 남음(`show_params` 출력으로 확인)
- 파라미터가 바뀌면 NMPC 솔버가 다시 생성됨(파라미터 해시)

## 결정 필요

- **실물 `/joint_states` 오른쪽 부호**: (a) `pinky_soccer_bringup`의 `wheel_joint_state_relay`에서 실물만
  오른쪽 부호를 뒤집어 시뮬레이터와 같은 규약으로 만들기(공식 코드 무수정, 보정 UI·RViz 바퀴 표시도 함께 맞음),
  또는 (b) 각 사용처에서 `joint_sign`으로 처리. (a)를 권장하며 `_bringup` 수정이라 확인이 필요합니다.

## 참고: MuJoCo에서 확인한 것 (실물 아님)

- 바퀴 응답: 74.9 rad/s² 경사 + τ ≈ 0.017 s, 지연 0 (검증 세트 상대 RMS 1.6 %)
- 유효 기하가 공칭값과 다름: 직진 속도 약 5 % 작음(유효 반경 ≈ 0.0266 m), 유효 바퀴 간격 ≈ 0.1017 m(공칭 0.0971)
- 한 바퀴가 거의 멈춘 피벗 회전은 크게 미끄러짐(속도 0.030 vs 모델 0.095 m/s) → 미끄러짐 없는 모델의 한계
- 결론: 시뮬레이터에서도 유효 기하 보정이 필요하며, 실물은 더 큰 차이가 있을 수 있음
