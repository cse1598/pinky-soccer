# 행동 검증 모드 (behavior verifier)

경기에서 실제로 쓰는 행동(BT 액션 노드)과 조합 행동(서브트리)을 **하나씩 골라 실행**하고,
로봇이 이해한 세계(월드 모델) 위에서 **어떻게 움직이는지 보고 평가**하는 도구입니다.
시뮬레이션과 실물에서 같은 창, 같은 C++ 행동 노드, 같은 제어기가 동작합니다.
그래서 시뮬레이션에서 리허설한 그대로 실물에서 확인할 수 있습니다.

## 실행

```bash
# 시뮬레이션 (정답 위치 겹쳐 보기, 우클릭으로 공 옮기기 가능)
ros2 launch pinky_soccer_viz game.launch.py mode:=mujoco verify:=true
ros2 launch pinky_soccer_viz game.launch.py mode:=gazebo verify:=true

# 실물: 로봇 robot.launch.py는 평소처럼 로봇에서 실행해 두고 PC에서
ros2 launch pinky_soccer_viz game.launch.py mode:=real verify:=true
```

- 경기용 `game.launch.py`와 같은 구성(인식·위치 추정·월드 모델·bt_node·제어기·RViz)에
  **행동 검증 창이 하나 더** 열립니다. `headless:=true`여도 검증 창은 열립니다.
- 검증 모드에서 bt_node는 경기 트리(`Main`)를 돌리지 않습니다. **창에서 실행을 누를 때만**
  선택한 행동 하나를 실행하고, 그 외에는 STOP 목표를 냅니다. `/game/playing`도 필요 없습니다
  (전체 경기 판단 항목만 실행할 때 true, 정지할 때 false를 보냅니다).
- 제어기는 기본 NMPC(`controller:=mpc`, `pinky_soccer_mpc` README)입니다. 속도 상한은 경기와 같이
  `max_lin`, `max_ang`입니다: 실물 기본 0.08 m/s·0.5 rad/s, 시뮬레이션 기본은 바퀴 한계(제품 사양 90 %)
  와 회전 2 rad/s.
- 여러 로봇: `robot_name`을 주면 검증 창도 그 로봇 네임스페이스의 토픽을 씁니다. 시뮬 `robots:=2`면
  상대의 정답 화살표(`/<상대>/ground_truth`)와 LiDAR로 추정한 상대가 지도에 함께 나옵니다. 장애물 모드
  (`opponent_mode:=static|lateral|longitudinal`)와 함께 이동 검증에 쓸 수 있습니다.
- **실물**: 사람이 로봇 옆에서 전원 스위치를 잡고 있는 상태에서만 실행합니다. 창의 정지 버튼,
  Esc, Space가 STOP을 보냅니다. 창이 꺼지거나 멈추면 bt_node가 1.5초 안에 스스로 멈춥니다.
  기존 command watchdog(0.5초)도 그대로 동작합니다.

## 화면

```
┌ 행동 목록 ─┬ 설명 / 입력 / 실행 ──────────┬ 2D 지도 ───────────────────────────┐
│ 단일 행동  │ 이름, 설명                   │ 경기장·골대·선                      │
│  지정 위치 │ 입력(수정 가능): 숫자 + 설명  │ 내 로봇(하늘)·공(주황)·상대(빨강)    │
│  공 뒤 ... │ 자동 입력(읽기 전용, 현재 값) │ 목표(자홍)·경유점(분홍)·예상 경로(보라)│
│ 조합 행동  │ 결과의 의미                  │ 지나온 길·시작 시 예상(회색)         │
│ 전체 경기  │ ▶실행 ■정지 ↻다시 제한시간    │ [시뮬] 정답: 공=빨간 점, 나/상대=화살표 │
│            │ 상태·현재 목표·명령 속도      ├ 노드 상태 | 조건 | 평가 | 기록 ──────┤
└────────────┴──────────────────────────────┴────────────────────────────────────┘
```

| 영역 | 내용 |
|---|---|
| 행동 목록 | `pinky_soccer_bt/config/verify_catalog.yaml`. 지금 경기 트리가 쓰는 단일 행동만 보입니다. 조합 행동(공격·수비·공 탐색·전체 경기)과 이동 외 단일 행동은 2026-11-24부터 `enabled: false`로 숨김(스킬을 하나씩 검증하는 동안, 지금은 "지정 위치로 이동"만). 정지는 정지 버튼/Esc로 계속 할 수 있습니다. bt_node도 `verify_subtrees:=false`(기본)면 서브트리 요청을 거부합니다 |
| 입력 (수정 가능) | 그 행동의 숫자 입력. 기본값은 **경기 트리에서 쓰는 값**과 같습니다(테스트로 확인) |
| 자동 입력 | 로봇 자세·공·상대·골대처럼 월드 모델에서 자동으로 들어가는 값. 보기만 합니다 |
| 결과의 의미 | SUCCESS/FAILURE/RUNNING이 이 행동에서 무엇을 뜻하는지 |
| 노드 상태 | 실행 중인 트리의 노드별 상태(RUNNING 노랑·SUCCESS 초록·FAILURE 빨강). 조합 행동에서 어느 분기가 도는지 보입니다 |
| 조건 | 경기 트리의 조건(BallKnown, IsBehindBall 등)을 **같은 기준값으로** 실시간 판정 |
| 평가 | 실행 1회의 결과·시간·이동 거리·목표 오차·위치 추정 오차(시뮬)·공 이동·득점·행동 전환 횟수·명령 속도 |
| 기록 | 이번 세션의 실행 목록. 더블클릭하면 그 입력값을 다시 불러옵니다 |

## 조작

| 조작 | 동작 |
|---|---|
| 목록 클릭 / 더블클릭 | 선택 / 바로 실행 |
| Enter, ▶ 실행 | 선택한 행동 실행 (실행 중이면 새 요청으로 교체) |
| Esc, Space, ■ 정지, 비상 정지 | 즉시 STOP |
| F5, ↻ 다시 | 마지막 실행을 같은 입력으로 다시 |
| 지도 클릭 | 위치 입력이 있는 행동(지정 위치로 이동)의 목표 x, y |
| 지도에서 끌기 | 누른 곳 = 위치, 끄는 방향 = 목표 방향 (Shift = 15° 단위) |
| 지도 더블클릭 | 위치를 찍고 바로 실행 |
| 지도 우클릭 (시뮬 전용) | 공을 그 자리로 옮김(정지 상태) |
| 체크박스 | 정답 위치(시뮬 전용)·지나온 길·예상 경로·불확실성(2σ 타원)·0.25 m 격자 |
| 완료 조건 자동 종료 | 끝나지 않는 행동을 조건으로 끝냄: 공 뒤로 자리 잡기는 IsBehindBall이 참일 때, 공 밀기·공격은 공이 골대에 들어갈 때 |

## 지도에 그리는 것

- **추정(로봇이 이해한 세계)**: `/world_model` 그대로. 관측 = 실선, 추정 = 점선, 분실 = X,
  불확실성 = 2σ 타원. 실물과 시뮬 모두 같은 방식입니다.
- **목표·경유점**: bt_node가 낸 `/behavior_goal`의 target과 `planned_path`
  (공 뒤로 자리 잡기는 옆 우회점 → 공 뒤 자리 순서).
- **예상 경로(보라 점선)**: 기본 NMPC 제어기에서는 제어기가 매 주기 계산한 최적 예측 궤적
  (`/mpc/predicted_path`, 1.5 s)을 그대로 그립니다. `controller:=reactive`면 비례 제어 식을 현재 추정
  자세에서 굴려 본 미리보기입니다. 목표가 바뀌면 바로 다시 그려집니다. 회색 점선은 실행 시작 직후의
  예상 경로로, 실제 지나온 길과 비교할 수 있습니다.
- **정답(시뮬 전용, 끄고 켤 수 있음)**: 공 = 빨간 점, 내 로봇 = 연두 화살표, 상대 = 분홍 화살표
  (시작점 = 위치, 방향 = 바라보는 방향). MuJoCo는 `/ground_truth`·`/sim/ball_ground_truth`
  (eval bridge), Gazebo는 `gazebo_truth_relay`가 월드 자세 스트림에서 같은 토픽을 만듭니다.
  지금 시뮬레이터에는 상대 로봇이 없어 상대 정답 화살표는 `/sim/opponent_ground_truth`가
  생기면 표시됩니다. 정답값은 표시·평가에만 쓰고 판단 입력으로 쓰지 않습니다.

## 기록 파일

`~/.ros/pinky_soccer/verify/<시작 시각>/` (`log_dir` 파라미터로 변경)

- `runs.csv`: 실행 번호, 행동, 입력값, 평가 항목 요약
- `run_<번호>_<행동>.csv`: 약 15 Hz 표본(시각, 추정/정답 자세, 공, 명령 속도, 행동, 목표)

## 동작 원리 (구현)

```
behavior_verifier (Tk) ──/behavior_test/request (JSON)──▶ bt_node verify_mode
          ▲                                                  │ 같은 factory·soccer_1v1.xml로
          │◀──/behavior_test/status (JSON, 매 tick)──────────┘ ReadWorldModel + 선택 노드 트리 생성
          │◀──/behavior_test/models (노드 포트/기본값, latched)    → /behavior_goal → reactive_controller
          │◀──/world_model, /behavior_goal, /cmd_vel
          │◀──(시뮬) /ground_truth, /sim/ball_ground_truth
          └──(시뮬) /sim/set_ball ──▶ MuJoCo eval bridge / gazebo_truth_relay
```

- 요청·상태는 `std_msgs/String`의 JSON입니다(새 메시지 타입 없음). 형식은
  `pinky_soccer_bt/include/pinky_soccer_bt/verify_mode.hpp` 머리말에 있습니다.
- bt_node는 요청한 노드 이름과 포트를 C++ 노드 모델로 검사하고(없는 노드·포트·숫자가 아닌 값 거부),
  월드 입력 포트(pose, ball, …)는 자동으로 연결합니다.
- 실행 시간과 제한 시간은 노드 시계(시뮬은 시뮬 시간), 창 연결 확인(1.5초)은 실제 시간입니다.

## 알려진 한계

- 예상 경로는 미리보기입니다(위 설명). Nav2 경로 계획은 아직 없습니다.
- 트리 안의 `Timeout` 데코레이터(공 탐색 2초·5초)는 BehaviorTree.CPP가 실제 시간으로 잽니다.
  시뮬이 실시간보다 느리면 시뮬 시간으로는 더 짧게 끝납니다(경기 실행도 같음).
- 실물에는 정답 위치가 없으므로 평가는 추정값 기준입니다. 실물 목표 오차는 줄자로 따로 재야 합니다.
- 공 옮기기는 시뮬 전용이며 공을 정지 상태로 놓습니다. 로봇 순간 이동은 위치 추정을 깨므로 넣지 않았습니다.
