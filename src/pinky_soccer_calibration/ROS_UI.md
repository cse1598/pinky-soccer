# ROS 캘리브레이션 스튜디오

Jupyter 없이 PC에서 실행하는 안내형 UI입니다. 장치 연결은 로봇 launch가 담당합니다. 기존 `camera_workbench`는 이전 프로토타입이며 새 진입점은 `calibration_ui`입니다.

## 실행

```bash
cd ~/pinky-soccer
source /opt/ros/jazzy/setup.bash
colcon build --symlink-install --packages-up-to pinky_soccer_calibration pinky_soccer_sim
source install/setup.bash
# 실제 로봇 터미널에서 (신규 센서 드라이버 실물 호환성 확인 필요)
ros2 launch pinky_soccer_bringup robot.launch.py imu_enabled:=true adc_enabled:=true
# 또는 PC에서 리허설 (하나만 실행)
ros2 launch pinky_soccer_sim mujoco_soccer.launch.py viewer:=false imu_enabled:=true adc_enabled:=true
# 별도 PC 터미널에서
ros2 run pinky_soccer_calibration calibration_ui
```

UI에서 환경을 `real` 또는 `rehearsal`로 선택하고 로봇 식별명·저장 폴더를 지정하세요. PC/로봇의 domain·DDS·네트워크는 미리 맞아 있어야 합니다. 시뮬레이션 ROS 시각으로 기록하려면 UI 실행 시 `--ros-args -p use_sim_time:=true`를 추가하세요. 장치 로그인/연결 버튼은 없습니다.

실물 서버는 `/camera/capture_frame`을 제공하는 최신 `pinky_soccer_msgs`·bringup으로
갱신/빌드하고 카메라 launch를 재실행해야 합니다. [배포 안내](../pinky_soccer_bringup/CAMERA_CAPTURE.md).
서비스가 없는 기존 서버도 JPEG 미리보기는 보이지만 원본 촬영은 오류 안내 후 중단합니다.

### 미리보기와 촬영

기본 실행은 ROS 카메라를 사용합니다. 웹캠 리허설은 아래 실행 옵션으로 별도 시작합니다.

- 실시간 영상과 체커 코너 표시는 `/camera/image_raw/compressed`의 JPEG를 디코딩해 사용합니다.
  UI는 `/camera/image_raw`를 구독하지 않으며 기록을 시작해도 원본 스트림 구독을 만들지 않습니다.
- **원본 사진 촬영·바닥 보드 촬영** 버튼은 `/camera/capture_frame`에 raw 한 장을 요청합니다.
  미리보기의 왜곡 제거·코너 주석·화면 축소가 적용되지 않은 원본으로 저장·계산합니다.
  서비스 실패/시간 초과 시 JPEG나 과거 사진으로 대체하지 않습니다.
- 촬영 요청 중에도 미리보기는 계속 갱신되며, 영상 아래에 원본 수신·저장 시각/크기/경로를 표시합니다.
  미리보기에서 인식 성공이어도 버튼 촬영 순간의 원본 자세·초점이 달라지면 채택되지 않을 수 있습니다.
- 기록 중에는 JPEG와 센서 원본 메시지를 Bag/CSV에 보존하고, 촬영할 때만 서비스 원본을
  `/calibration/capture/image_raw` 및 `/calibration/capture/camera_info` Bag 채널에 기록합니다.
  이 두 채널은 파일 기록용이며 네트워크 영상 토픽을 추가 발행·구독하지 않습니다.
- 다른 프로그램이 raw를 구독하거나 별도 원본 기록 CLI를 실행하면 해당 원본 전송은 계속됩니다.
  카메라 서비스 이름·대기 제한은 `capture_service`·`capture_timeout` ROS 파라미터로 지정합니다.

## 노트북 웹캠 리허설 (`-webcam`)

로봇과 시뮬레이터 없이 PC의 로컬 V4L2 웹캠을 사용합니다. 소스 선택은 **시작 명령에서만** 가능하며
UI에 카메라/ROS 전환 버튼을 두지 않습니다. 기본 실행은 기존 ROS 입력을 그대로 사용합니다.

```bash
source ~/pinky-soccer/install/setup.bash
# 기본 웹캠 0, 요청 해상도640×480 / 15fps
ros2 run pinky_soccer_calibration calibration_ui -webcam
# 다른 장치/요청 해상도 (지원 여부는 드라이버에 따라 다르며 실제 수신 크기로 보정합니다)
ros2 run pinky_soccer_calibration calibration_ui -webcam /dev/video2 \
  --webcam-width 1280 --webcam-height 720 --webcam-fps 15
# launch에서 선택할 수도 있습니다
ros2 launch pinky_soccer_calibration calibration_ui.launch.py webcam:=true webcam_device:=0
```

웹캠 실행 시 `rclpy.init`/DDS 연결·로봇 센서 구독·주행 명령 발행을 하지 않습니다.
따라서 핑키용 네트워크/DDS 설정을 변경하거나 로봇 bringup을 실행할 필요가 없습니다.
ROS 메시지와 기존 Bag/CSV 저장 코드를 오프라인에서 재사용합니다. 바퀴·LiDAR·초음파·IMU 탭은
비활성화되고, 환경은 rehearsal·장치는 webcam으로 고정됩니다. 가짜 로봇 센서값을 생성하지 않습니다.

### 웹캠 진행 순서

1. **새 프로젝트**를 만들고 **기록 시작/재개**를 누릅니다. 웹캠 종류·해상도는 프로젝트에 기록됩니다.
   같은 소스의 웹캠 프로젝트는 **저장 폴더 불러오기**로 이어갈 수 있습니다. 핑키 프로젝트와 상호 혼용은 거부합니다.
2. **카메라 보정** 탭에서 체커보드 내부 코너 수·실측 칸 길이를 입력하고 원본 사진을 촬영합니다.
   노트북 자동 초점이 바뀌면 내부값도 바뀔 수 있으므로 초점/줌/해상도 등 사용 조건을 일정하게 유지하세요.
   학습15장 이상/독립 검증8장 이상 분류 후 **현재 사진으로 보정·독립 검증**을 진행합니다.
3. **장착** 탭에서 보드를 수평 바닥에 평평하게 놓고 웹캠을 고정한 뒤 촬영합니다. 검증한 내부값으로
   바닥에서 광학 중심까지 높이·roll/pitch를 추정하며, 5회 이상 반복을 권장합니다. 코너 순서로 인해
   보드 법선이 뒤집힌 경우 높이/기울기 모드에서 바닥 위쪽 방향을 맞춥니다(전체 로봇 pose 추정은 아님).
4. **공 인식 검토** 탭에서 주황색 공을 봅니다. 웹캠 프로젝트의 현재 높이/roll/pitch를 사용하여 경기의
   공통 투영/추적 함수를 실행합니다. 로봇 TF나 로봇 기본 설치각을 빌려 쓰지 않습니다.
   `webcam_floor` 원점은 **카메라 광학 중심을 바닥에 수직으로 내린 점**입니다. yaw=0은 로컬 축의 정의이고
   측정한 로봇 방위가 아닙니다. X/Y는 이 로컬 바닥 좌표, 거리는 원점에서 공 중심까지의 수평 거리입니다.
   바닥에서 원점을 표시하고 공 중심의 수직 투영점까지 줄자로 재어 표시 거리와 비교하세요.
5. 카메라/노트북 위치나 화면 각도가 바뀌면 바닥 보정을 다시 촬영합니다. 오래된 측정값이 현재 배치와
   일치하는지는 자동으로 알 수 없습니다. 내부 사진/분류를 바꿔 재계산한 경우 장착 기록도 다시 계산하세요.
6. 프로젝트/프로필을 저장합니다. `image_source.kind: webcam`, 장치, 실제 해상도와
   `environment: rehearsal`을 보존합니다. 실물 launch는 rehearsal 프로필을 거부합니다.
   웹캠 보정값은 핑키 카메라의 보정값이 아니므로 실물 연결 시 정상 ROS 모드에서 별도 프로젝트로 측정합니다.

웹캠 HFOV는 자동으로 알 수 없으므로 핑키의66°를 기본값으로 사용하지 않습니다. 내부값이 없으면
처음에는 픽셀만 표시합니다. 명시적으로 알고 있는 HFOV 가정을 쓰려면
`--webcam-hfov-deg <도>` 또는 `webcam_hfov_deg:=<도>`를 지정할 수 있으며 미보정 추정으로 표시됩니다.
HFOV 가정만으로 높이·기울기가 생기는 것은 아니므로, 거리 계산에는 장착 측정값도 필요합니다.

웹캠은 별도 프로세스에서 읽어 드라이버 정지 시 종료할 수 있게 했습니다. 미리보기는 JPEG,
촬영은 **요청 뒤 새로 읽은 BGR 프레임**을 PNG로 보존합니다. 이는 OpenCV가 반환한 영상이며
센서 Bayer RAW라는 뜻은 아닙니다. 시각은 같은 PC의 **읽기 완료 시각**으로 실제 노출 시각은 아닙니다.
촬영 실패/장치 없음에는 과거 사진이나 합성 영상을 자동 대입하지 않습니다.

장치가 보이지 않으면 `/dev/video*`, 카메라 사용 권한, OS 개인정보 카메라 허용 및 다른 앱의 점유를
확인하세요. `ros2 run ... -webcam`과 기본 ROS UI는 서로 다른 시작 방식이며 소스 변경 시 재실행합니다.

## 진행

### 계속 사용하는 프로젝트

카메라의 설정·촬영·파일 추가·사진 분류/삭제·선택 사진 미리보기·계산/검증은
**카메라 보정** 한 탭에 통합했습니다. 왼쪽은 실시간 영상, 오른쪽 목록 옆은 선택한 저장 사진입니다.
**현재 사진으로 보정·독립 검증** 버튼 하나로 현재 분류에 맞춰 재학습/검증하고
같은 화면에서 사진 장수·재계산 필요·검증 통과/실패·RMS 평균/최대/표준편차를 확인합니다.
기존 사진 관리 탭과 탭 이동 버튼, 별도 학습 계산 버튼은 제거했습니다.
바퀴/센서 실험 기록은 **측정 기록** 탭에 유지합니다. 저장 파일/프로젝트 형식은 같습니다.

- **새 프로젝트 / 저장 폴더 불러오기 / 프로젝트 저장**을 분리했습니다. 생성 시 하위 프로젝트 폴더와 `project.yaml`을 만들고, 불러오면 로봇 식별명·실물/리허설·보드 설정·사진 분류·측정값·결과를 복원합니다. 변경 내용과 종료 시 상태를 저장합니다. 같은 폴더의 동시 편집은 잠금으로 방지합니다.
- **기록 시작/재개 → 기록 종료**는 원본 수집만 제어합니다. 종료해도 검토/재계산이 가능하며, 재개 시 기존 Bag/CSV를 덮어쓰지 않고 새 `raw_bag_<ID>`/`observations_<ID>.csv`를 추가합니다.
- **카메라 보정:** 학습/검증 장수와 사진 미리보기·출처를 확인합니다. 다중 선택하여 검증으로 보내거나 학습으로 되돌리고, 파일 추가·삭제할 수 있습니다. 검증으로 분류하지 않은 활성 사진은 학습 자료입니다. 촬영 후에도 추가 가능합니다. 파일 추가 자료는 ROS 원본으로 확인한 자료와 출처를 구분합니다.
- **측정 기록:** 전진/후진/좌회전/우회전 횟수·실측값 및 센서/장착 회차를 표시합니다. 선택하면 입력·관절 회전량·원시 표본·출처를 상세 확인합니다. 잘못된 기록 삭제 후 해당 항목의 기록을 선택해 **선택 항목 다시 계산**을 누릅니다.
- 삭제는 계산 목록에서 제외하는 방식으로 `deleted` 이력과 원본 사진/Bag/CSV는 보존합니다. 관련 결과는 **재계산 필요**로 표시됩니다. 사진 변경은 카메라·장착 결과를 무효화합니다. 계산은 이전 결과를 초기화하며 실패해도 이전 값이 유효한 결과로 남지 않습니다.
- **프로젝트 저장**은 미완료 자료도 저장합니다. **결과·프로필 저장**은 현재 유효한 계산 결과만 내보냅니다. 모든 항목을 완료할 필요는 없으며 미계산 항목 목록도 프로필에 기록합니다.
- 기존 ROS UI `session.yaml` 폴더도 불러옵니다. 예전 자료의 원시 표본이 없으면 **이전 분석값(원시 표본 없음)**으로 표시하며 없는 표본을 만들지 않습니다. IMU 새 표본과 합산하지 않은 경우 결과에 명시합니다. 새 수집부터는 재계산용 표본도 저장합니다.
- 완료한 미저장 바퀴 주행은 임시 기록되어 재열기 후 실측값을 입력할 수 있습니다. 주행 중 편집/프로젝트 전환을 막고 종료·즉시 정지는 가능합니다.

`project.yaml`이 현재 상태의 기준 파일입니다. 함께 저장되는 결과/실험 YAML은 외부 검토용이며 직접 편집해도 프로젝트 상태에 자동 반영되지 않습니다. 폴더는 UI로 관리하세요.

### LiDAR 경기장 모양 저장

1. 로봇/시뮬레이터 센서 launch를 실행하고 보정 UI에서 프로젝트를 만들거나 불러옵니다.
2. **센서 모니터 → LiDAR 화면**에서 벽의 윤곽과 수신 상태를 확인합니다.
3. 경기장 안 사람·장애물을 치우고 로봇을 정지합니다. **LiDAR** 탭에서 정지/정리 확인을 체크한 뒤
   **현재 LiDAR 경기장 모양 저장**을 누릅니다. 기본 지도 해상도는0.01m/픽셀입니다.
   **기록 시작**은 필요하지 않습니다. 웹캠 전용 모드에서는 사용할 수 없습니다.

프로젝트의 `lidar_fields/시각_식별자/`에 다음 파일이 즉시 보존됩니다. 반복 저장은 새 폴더를
만들며 기존 관측과 보정값·`profile.yaml`은 덮어쓰지 않습니다. 프로젝트를 다시 열어도 저장 개수와
최근 지도 경로를 LiDAR 탭에서 확인할 수 있습니다.

- `map.yaml` + `map.pgm`: Nav2 map_server에서 읽을 수 있는 점유 지도(검정=관측된 벽,
  흰색=레이가 통과한 공간, 회색=미확인). 화면 표시 반경과 관계없이 유효 레이를 모두 사용합니다.
- `scan.yaml` + `scan.csv` + `raw_bag/`: 원본 LaserScan 전체 필드·모든 레이/유효 여부/변환 점군,
  원본 CDR 메시지를 보존합니다. 수신된 odom도 있으면 Bag에 함께 저장합니다.
- `observation.yaml`: 원본 프레임·시각·해상도·센서→저장 좌표 변환·모델 해시·파일 해시·제약.
  모델을 수신한 경우 `robot_description.urdf`도 함께 보존합니다.

**좌표 기준:** 모델이 있으면 저장 당시 `base_link`의 XY 원점/방향을 기준으로 하고, 해당 센서의
고정 변환을 모르면 원본 LiDAR 좌표를 사용합니다. 경기장 중앙이나 범퍼 원점으로 가정하지 않습니다.
범퍼는 자로 잰 거리 입력의 기준이며 지도 좌표 원점과 별개입니다. 미래의 위치 추정에서는 이 지도
좌표에 맞춘 초기 자세와 센서 TF가 필요합니다. 자동으로 기존 AMCL 지도/launch에 적용하지 않습니다.
기존 경기장 좌표와 맞추기 쉽게 하려면 로봇을 경기장 중앙에서 파란 골대를 향하게 두고 저장하세요.
중앙 배치·골대 방향을 프로그램이 자동으로 알아내거나 보정하는 기능은 아닙니다.

**한계:** 현재 스캔1장 기준이며 SLAM이나 여러 위치의 스캔 합성이 아닙니다. 가려진 벽·레이 사이의
미관측 공간은 추측하지 않습니다. `NaN`/무한대/범위 밖 레이는 원본에 보존하되 지도를 채우지 않으며,
정확히 최대 거리인 레이는 통과 공간만 표시합니다. 수신 단절·유효 벽 레이 부족·감지된 이동은 저장을
거부합니다. odom이 없으면 정지 여부는 사용자의 확인에 의존합니다. 대칭 경기장의180° 방향 구분은
여전히 골대 색/초기 방향 등의 추가 단서가 필요합니다. 지도 형태는
[Nav2 Jazzy map_server 형식](https://api.nav2.org/nav2-jazzy/html/map__io_8cpp_source.html)을 따릅니다.

### 공 인식 검토

공 검색 영역은 경기와 동일하게 기본 **영상 아래 2/3**입니다. 위 1/3은 폼보드 벽 밖 배경을
제외하는 고정 영역으로, 공 검토 영상에 어둡게 표시됩니다. 흰 벽 자동 검출은 아니며 카메라 배치가
달라지면 경기 설정 YAML의 `detection_top_fraction`을 조정해 같은 설정 파일을 선택하세요.
내부 보정·장착용 체커보드 인식 및 원본 촬영은 전체 영상을 사용합니다.

로봇/시뮬레이터 센서 launch와 기존 UI만 실행한 뒤 **공 인식 검토** 탭을 선택합니다.
프로젝트 생성이나 기록 시작 없이도 동작하며, 주황색 공을 움직여 검출·거리를 확인할 수 있습니다.
왼쪽 JPEG 영상에 공 후보의 원/중심을 표시하고, 오른쪽에 픽셀 좌표·반경·면적,
현재 관측 X/Y/Z·수평 거리·방위각, 필터 추적 좌표·OBSERVED/ESTIMATED/LOST·σ·관측 경과 시간을 표시합니다.
base_link 출력이면 범퍼 앞면 중앙 기준 공 중심 X/Y도 표시합니다. 좌표/거리의 기준점과 단위를 구분하세요.

- **경기와 공통 코드:** `pinky_soccer_world_model.robust_ball.BallImageDetector`(HLS/색 윤곽·가시 원호 최소제곱 피팅·단일 후보 연결),
  `ball_vision.project_ball`(왜곡을 고려한 픽셀 광선과 공 중심 높이 평면의 교점),
  `ball_vision.annotate_ball`, `BallFilter`를 직접 재사용합니다. 경기 노드도 같은 투영/표시 함수를 호출합니다.
  검토 전용 토픽이나 주행 명령을 발행하지 않으며 경기의 `/ball_detection`·월드모델을 덮어쓰지 않습니다.
- **새 검출 표시:** 최대 하나의 현재 공만 표시합니다. 원호 지지율과 휴리스틱 검출 점수(확률 아님),
  가림/반사광 복원 여부를 보여줍니다. 복원 윤곽은 황색 점선입니다. 완전 가림/완전 백색 포화는
  영상 근거가 없으므로 미검출이며, 같은 색의 둥근 물체 오인식을 완전히 보장할 수는 없습니다.
- **내부 보정 선택 순서:** 명시적으로 선택한 카메라 YAML/프로필 → 현재 프로젝트의 독립 검증 통과 값
  → 크기가 맞고 유효한 실시간 CameraInfo → 미보정 HFOV 가정입니다. 출처를 화면에 표시합니다.
  선택 파일을 해제하려면 **자동 보정 선택**을 누릅니다. 보정 파일의 해상도가 맞지 않으면 임의로
  확대/축소하거나 HFOV로 대체하지 않고 픽셀 검출과 오류를 표시합니다.
- **보정값이 없을 때:** 기본 **미보정 거리 추정**을 사용하며 HFOV 66°(경기 테스트 모드와 같은 공식
  시뮬레이터 기반 가정), 왜곡 0, 실행 중 카메라 TF로 추정합니다. 이는 실측 보정이 아니며
  화면/영상에 APPROXIMATE를 표시합니다. 옵션을 끄면 보정이 없는 상태에서는 픽셀만 표시합니다.
- **장착/좌표:** 현재 프로젝트의 유효한 장착 높이/roll/pitch를 우선 적용합니다. 카메라 YAML/프로필을 직접 선택한 경우 해당 파일의 장착값을 사용합니다. 측정하지 않은 X/Y/yaw는 실행 TF를 유지하고 임의로 생성하지 않습니다. 장착값이 없으면 기존 TF를 사용합니다. 5회 반복 검증 전의 값도 검토에 사용할 수 있지만 화면에 미완료로 표시합니다. 오래되거나 삭제 후 재계산하지 않은 장착값은 적용하지 않습니다. TF/바닥 교점이 없거나 최대 거리(기본2.5m)를 넘으면 미터 좌표를 만들지 않습니다. 바닥 기준 공 중심 Z는 0.02135m이고 base_link 원점이 0.028m 높이면 표시 Z는 −0.00665m입니다.
- **추적:** 경기의 Kalman+마찰 `BallFilter`를 map, 없으면 odom 고정 좌표계에서 사용하고 현재 출력
  프레임으로 변환하여 표시합니다. 고정 프레임 TF가 없으면 현재 관측만 표시하고 추적을 기다립니다.
  영상/PC ROS 시각 차이가2초를 넘으면 추적을 보류합니다. 영상이 끊기면 현재 값과 추적을 초기화하며,
  새 영상에서 공이 안 보일 때만 필터의 ESTIMATED/LOST 상태를 구분합니다.
- **설정과 비교:** 설치된 경기 `ball_detector.yaml`/`world_model.yaml`을 기본으로 읽습니다.
  별도 경기 설정을 사용한다면 **경기 검출/월드모델 설정 YAML 불러오기**로 같은 파일을 선택하고,
  HLS·공 크기·180° 반전·가정 HFOV도 맞추세요. 실행 중 경기 노드의 별도 launch/CLI 파라미터를
  자동 조회하거나 수정하지는 않습니다. UI의 반전/가정값 변경도 경기 노드에는 자동 반영되지 않습니다.
  검토는 JPEG/화면 갱신 속도 기준이며 경기 원본 영상과 후보 픽셀·필터 값 차이가 생길 수 있습니다.
  전체 월드모델의 경기장 벽 제약·자기 위치 추정·탐색 지도는 이 카메라 검토 탭에서 재현하지 않습니다.

### 실시간 센서 모니터

UI 첫 탭 **센서 모니터**는 새 실험/기록을 시작하지 않아도 작동합니다. 로봇 연결은 기존 launch와 ROS 통신 설정을 사용합니다.

- **전체 센서:** 배터리 잔량(%, `/battery/percent`)·전압(V)·ADC BatteryState, IMU quaternion/센서 프레임 기준 RPY(deg)·각속도(rad/s)·가속도(m/s²), LiDAR 유효 레이/최단·최장 거리, 초음파 거리/감지 범위, 적외선 좌·중앙·우 ADC 원시값, odom 위치·자세·속도, 관절 위치/속도, 카메라 해상도·인코딩·내부 행렬, 제어 명령을 표시합니다. 아래쪽 항목은 스크롤해서 확인합니다.
- **LiDAR 화면:** 표시 반경을 조정하는 XY 점군 화면입니다. 실행 모델의 센서 좌표가 있으면 base_link로 변환하고, 없으면 원래 센서 프레임으로 표시합니다. 위쪽 +X, 왼쪽 +Y이며 좌표 원점을 적색 십자로 표시합니다. 최대 1,500점을 그리며 전체 레이는 원본 상세에 그대로 있습니다.
- **원본 상세:** 토픽을 선택하면 전체 ROS 메시지를 약 1초 간격으로 표시합니다. LiDAR 전체 ranges/intensities, IMU 공분산·원본 `/imu_native`, 카메라 전체 K/D/R/P, 배터리 전체 필드도 여기서 확인합니다. 영상 바이트는 텍스트 대신 왼쪽 미리보기로 봅니다.

수신 여부·마지막 수신 후 경과 시간·최근 최대 30표본의 수신 주파수를 함께 표시합니다. 배터리 Float32 토픽은 실제 발행 주기 5초를 고려해 15초까지 정상으로 보고, 센서별 기한이 지나면 마지막 값을 회색으로 표시합니다. **미수신은 비활성/네트워크 단절/미장착을 자동으로 구별했다는 뜻이 아닙니다.** launch 옵션과 통신을 확인하세요. NaN·알 수 없는 배터리 잔량·잘못된 quaternion을 0으로 채우지 않으며, 초음파 ±inf는 범위 초과/미검출로 구분합니다. IMU yaw는 센서가 제공하는 상대 자세이며 경기장 절대 방위로 표시하지 않습니다.

모니터 거리는 **센서 원점 기준 원본**입니다. 범퍼에서 잰 실측값의 자동 변환은 아래 보정 탭에서 수행합니다. 실물 IR ADC를 보정표 없이 거리로 환산하지 않습니다. 리허설 전용 `/sim/ir_*_link/distance`는 별도로 표시하며 실물에는 없습니다. 실측 표가 없는 리허설에서는 IR ADC가 미수신이어도 정상일 수 있습니다.

실험 기록을 시작하면 위 배터리·IMU 원본·리허설 IR 거리 토픽도 원본 Bag/CSV에 함께 보존합니다. 모니터는 주행이나 자동 보정 적용을 수행하지 않습니다.

### 항목별 실험

왼쪽 영상은 **기록 시작 전부터 체커보드 코너를 자동 표시**합니다. 카메라 탭의 내부 코너
가로·세로 수를 입력하면 미리보기에 반영됩니다. 기본9×6이면 성공 시 색상 코너/연결선,
0번·+X·+Y와 초록색 `인식 성공 · 내부 코너 9×6 = 54개` 상태가 표시됩니다.
전체 격자를 찾지 못하면 미검출 안내, 입력 중인 숫자가 잘못되면 설정 확인 안내를 표시하고
영상은 계속 보여 줍니다. 9×6은 내부 교차점 수이며 보통 칸은10×7입니다.
보드 전체가 화면에 들어오게 하고 반사·흔들림·초점을 확인하세요.
인식 표시는 사진 저장/보정 성공을 뜻하지 않습니다. 사진은 촬영 버튼으로
원본을 저장하며 코너 표시는 미리보기 사본에만 그립니다. 세션 촬영 후 보드 규격을 바꾸려면
기존 세션 제한에 따라 새 실험을 시작해야 합니다.

1. **새 프로젝트**에서 상위 폴더를 선택하거나 **저장 폴더 불러오기**로 기존 프로젝트를 엽니다. 촬영/수집/주행 전 **기록 시작/재개**를 누릅니다. 과거 자료 검토·파일 추가·분류·삭제·재계산은 장치/기록 연결 없이 가능합니다.
2. 카메라: 내부 코너 수·실측 칸 길이(기본9×6·30mm)를 설정합니다. **원본 사진 촬영** 또는 **사진 파일 추가**로 모아 학습15장 이상/검증8장 이상으로 분류합니다. **현재 사진으로 보정·독립 검증**은 현재 학습 사진으로 내부값을 매번 새로 계산한 뒤 검증 사진에서는 보드 자세만 추정해 평가합니다. 별도의 학습 계산 버튼 없이 한 번에 두 단계를 수행합니다. 모든 사진 RMS≤0.7px 및 검증 보드 중심 X/Y 범위 각각 화면25% 이상을 요구합니다. 사진 변경 후 다시 계산해야 합니다. 학습·검증 간 동일 사진은 거부합니다. 왜곡 제거 영상의 직선도 확인하세요.
3. 바퀴: 평평하고 넓은 바닥에 줄자·기준선·펜·각도 기준을 준비합니다. 아래 **전후진/회전 분리 측정** 절차로 각 실험을 저장한 뒤 바퀴를 추정합니다. 각 방향 3회 이상을 권장하며 계산에는 전진/후진/좌회전/우회전이 모두 포함된 최소 4회가 필요합니다. 보정 후 별도 실험에서 거리·각도와 펜 궤적을 다시 확인하세요.
4. LiDAR/초음파: 넓은 수직 벽/판을 **범퍼 앞면과 평행하게** 놓습니다. **범퍼 전면 바깥쪽 중앙에서 로봇 전방으로 벽까지 잰 거리(m)**를 입력하고, UI의 자동 변환값을 확인한 뒤 10초 수집합니다. 센서까지 줄자를 넣을 필요가 없습니다. 아래 측정 기준을 따르세요. 여러 거리에서 반복하면 평균·표본 표준편차·편향·유효 감지 비율을 저장합니다. 단일 벽으로 전체 외부 XYZ/RPY가 자동 추정되지는 않습니다.
5. IMU: 수평 바닥에서 완전히 정지한 채 10초 수집. gyro·중력 포함 가속도의 축별 평균/표준편차를 표시합니다. 회전 중 수집은 정지 바이어스 실험으로 인정하지 않습니다. 한 자세로 가속도 바이어스와 중력을 분리하지 않습니다.
6. 주기: 10초 수집으로 수신 간격·지터 확인. 실물 모드는 PC chrony와 `/calibration/time_sync_status`를 자동 확인합니다. 로봇을 기준으로 동기화 중이며 관측 오차 지표 합이 5ms 이하일 때만 header→수신 나이를 계산합니다. 이는 노출/센서 내부 처리까지 포함한 전체 지연이 아니고, 5ms도 보장 오차가 아닌 보수적인 검사 기준입니다. 미동기화 상태에서도 다른 보정은 가능하며 수동 확인 체크박스는 없습니다.
7. 장착: 아래 바닥 보드 절차로 영상에서 카메라 높이·각도를 추정합니다. 카메라 각도를 자로 재서 입력하는 화면은 제거했습니다.
8. 결과와 별도 검증을 확인한 뒤 사람 확인 체크 → **결과·프로필 저장**. 촬영/수집만으로 정확도가 보장되지 않으며 각 항목의 기준·오차·가정을 검토해야 합니다.

**보정 주행 속도:** 전후진은 0.08m/s, 좌우 회전은 0.30rad/s(약17.2°/s)입니다. 실물·Gazebo·MuJoCo에 동일하게 적용하며, 완료 기준은 `/odom` 이동거리1m 또는 누적 회전각360°입니다. 실제 속도는 모터·접촉 조건에 따라 달라질 수 있습니다.

**주행 정지:** UI 즉시 정지, 종료, odom/joint 수신 0.6초 이상 중단, 60초 제한 시 0 명령을 보냅니다. launch의 별도 command watchdog은 `/cmd_vel` heartbeat가 0.5초 끊기면 정지합니다. 따라서 다른 제어 프로그램도 명령을 주기적으로 보내야 합니다. 동시에 teleop/Nav2를 실행하지 마세요. 프로세스/전원 고장까지 보장하는 물리 비상정지는 아닙니다.

## 범퍼 기준 거리 측정

줄자의 0을 **범퍼 앞면의 바깥 표면 중앙**에 대고 로봇 전방(+X)으로 벽까지 수평으로 잽니다. 구멍 안쪽·초음파 캔·범퍼 링크 원점·범퍼 뒤쪽을 기준으로 삼지 마세요. 높이가 다른 센서도 같은 수직 벽을 보도록 판을 충분히 높고 넓게 준비합니다. 줄자가 비스듬하거나 벽이 범퍼 앞면과 평행하지 않으면 변환의 전제가 깨집니다.

실행 중인 `/robot_description`의 범퍼 visual STL/box 외곽과 고정 관절을 읽습니다. 범퍼 메시의 원점이 질량 중심이라서 `depth/2`를 단순히 더하지 않습니다. 모델의 base_link 기준 범퍼 앞면 X를 B, 센서 X를 S, 입력 거리를 d라 하면 정면 벽의 센서 기준 거리는 `d + B − S`입니다. LiDAR는 **로봇 전방** ±0.035rad 레이만 선택하고 각 레이를 벽 법선 방향으로 투영하여 비교합니다(센서 프레임이 뒤로 180° 돌아 있어도 처리). 초음파는 센서 +X 축과 벽의 교차 거리로 변환하며, 장착 축이 전방에서 5° 이상 벗어나면 정면 실험을 거부합니다. 빔 폭·반사 특성은 모델 위치 변환만으로 보정되지 않습니다.

모델/범퍼/센서 프레임을 읽지 못하면 임의 기본 오프셋으로 계산하지 않습니다. 기존 launch를 켠 뒤 UI 상태를 확인하세요. 측정 중 모델·프레임이 바뀌면 재수집해야 합니다. 실물 범퍼가 모델과 다르거나 센서 장착이 어긋났다면 먼저 형상/장착 정보를 맞춰야 합니다. 모델 좌표는 실측으로 확정한 값이라는 뜻이 아닙니다.

### 전후진/회전 분리 측정

- **전후진:** 범퍼 앞면 바깥 중앙의 바닥 투영점을 시작/정지 후 각각 표시합니다. **두 점 사이 직선 거리(m)** 하나만 입력합니다(전진 +, 후진 −). 예: 전진 102cm는 `1.02`, 후진 102cm는 `-1.02`. 좌우 편향 입력이나 그 값으로 각도 역산은 하지 않습니다. 출발 기준선과의 정렬 오차를 바퀴 비대칭으로 해석하지 않기 위함입니다. 펜 궤적은 직진성 확인에 사용하며 S자·큰 곡선·충돌·미끄러짐이 있으면 재실험하세요.
- **회전:** 좌/우 360° 실행 후 동체 방향 표시와 각도 기준으로 실제 **누적 회전각(deg)**만 측정하여 `회전 실측 저장`을 누릅니다. 좌회전 +358°, 우회전 -362°처럼 입력하며 한 바퀴 뒤 같은 방향이라고 0°로 넣지 않습니다. 이동 거리나 좌우 편향 입력은 사용하지 않으며 측정하지 않은 거리를 0으로 가정해 계산하지 않습니다.
- 매 주행은 목표 도달 후 해당 종류의 저장 버튼으로 한 번 저장합니다. 종류가 다른 버튼·누락/잘못된 부호·중단 실험은 거부하고, 정상 완료한 미저장 실험이 있으면 다음 주행을 막습니다. 전후진 도중/저장 전에 모델을 바꾸지 마세요.
- `전후진 실측 저장`은 `wheel_straight_trials.yaml`, `회전 실측 저장`은 `wheel_rotation_trials.yaml`에 분리 저장하며 `wheel_trials.yaml`은 두 종류를 합친 기록입니다. 좌우 바퀴 관절 변화·입력 실측값·변환값·실험 종류를 함께 보존합니다. 전후진에는 범퍼/바퀴축의 실행 모델 좌표·모델 해시와 원본 URDF도 남습니다.
- `반복 실험으로 바퀴 추정`은 전후진 실측 거리와 엔코더 평균 회전량으로 **공통 유효 반경**을, 좌/우 회전의 실측 누적 각도로 **유효 바퀴 간격**을 추정합니다. 전후진에는 각도 방정식을 추가하지 않고, 회전에는 이동 거리 0을 가정하지 않습니다. 거리/회전각만으로 좌우 개별 반경 차이를 충분히 식별할 수 없어 결과의 좌우 반경은 같은 공통값이며 `individual_radii_identified: false`로 표시합니다. 각 방향 3회 이상 반복하고 결과/프로필 저장으로 내보내세요.
- 엔코더 원본은 보존하고 실험 방향(전진 양쪽+, 후진 양쪽−, 좌회전 L−/R+, 우회전 L+/R−)으로 계산 시 부호를 정규화합니다. 결과의 `encoder_normalization`에 각 기록의 부호 배수를 남깁니다. 실물 오른쪽 역부호와 시뮬 양쪽 정방향 모두 처리하고 이미 맞는 부호를 다시 뒤집지 않습니다.
- **기존 프로젝트:** 이전 종방향/편향 기록은 원래 X/Y와 추정 각도를 지우지 않고, `sign(X)·hypot(X,Y)` 거리만 새 계산에 사용합니다. 편향에서 역산했던 각도는 새 추정에 사용하지 않습니다. 이전 방식의 바퀴 결과는 재열기 시 재계산 대상으로 바뀝니다. 원본 Bag/CSV는 변경하지 않습니다.
- 계산식: 전후진 `s = r·(ΔφL+ΔφR)/2`, 회전 `r·(ΔφR−ΔφL) = b·θ`. 각각 거리/회전각 실측 방정식으로 최소제곱 계산하며 종류별 평균/표본 표준편차와 잔차를 기록합니다. 거의 직선인 전후진 경로를 전제하므로 큰 곡선에서 시작~끝 거리와 실제 주행 경로 길이는 다릅니다.

## 저장과 적용

- `session.yaml`: 환경·로봇·시각, `raw_bag/`: 수신한 원본 ROS 메시지, `observations.csv`: 수신 시각·header 시각·분석 관측값.
- `captures/`: 서비스로 받은 모든 원본 PNG·`.capture.yaml`(검출/보정에서 거부된 사진도 보존).
  메타데이터는 capture_id·촬영 CameraInfo/시각·수신/요청 시각·원본 픽셀 SHA256을 포함합니다.
- `training/`, `validation/`, `floor/`: 채택된 원본 PNG와 같은 이름의 `.capture.yaml`.
  서비스 원본 Image/CameraInfo는 Bag, 파일 연결 정보는 CSV에도 보존됩니다.
- `wheel_trials.yaml`, `results.yaml`: 실측 입력과 계산/검증 결과.
- 거리 결과에는 범퍼~벽 입력, 자동 변환한 센서 기준 거리, 센서/범퍼의 모델 좌표, 비교 방식, 실행 모델 SHA256·URDF 파일명을 함께 보존합니다. 원본 Range/LaserScan은 변경하지 않고 Bag에 기록하며, CSV에는 분석용 관측값을 별도로 남깁니다. `robot_description_<해시>.urdf`와 Bag의 `/robot_description`도 보존합니다.
- `camera.yaml`: 독립 검증 통과한 ROS 내부 보정 파일.
- `profile.yaml`: 현재 유효하게 계산한 적용 프로필. `exports/<ID>/profile.yaml`과 카메라 YAML 스냅샷도 남겨 이전 프로필이 재계산으로 바뀌지 않게 합니다. 자료 변경 시 루트의 이전 프로필은 `exports/previous_*.yaml`로 보존하며 새로 내보내면 다시 생성합니다. 다른 PC로 옮기면 폴더 전체를 옮기고 프로젝트를 열어 프로필을 다시 내보내 절대 경로를 갱신하세요.

```bash
ros2 launch pinky_soccer_bringup robot.launch.py imu_enabled:=true adc_enabled:=true \
  calibration_profile:=/절대/세션/profile.yaml
# 같은 인자를 gazebo_soccer.launch.py, mujoco_soccer.launch.py에서도 사용
```

현재 UI 결과는 **실물 카메라 내부 YAML, 카메라 바닥 높이/roll/pitch, 공통 유효 바퀴 반경·간격, 가상 바퀴 형상/모델 설정**에 적용됩니다. 장착값은 공 검토에서 현재 프로젝트를 즉시 사용하며, 결과·프로필 저장 후 같은 `calibration_profile`로 로봇/시뮬 launch를 다시 실행하면 TF와 경기 검출에 반영됩니다. 장착 보정은 광학 중심 높이/기울기를 교체하고 미측정 X/Y/yaw는 모델 값을 유지합니다. 기존 전체 카메라 pose 프로필은 계속 지원하며 전체 pose가 있으면 그것을 우선합니다. 새 바퀴 결과는 좌우 개별 비대칭을 측정한 것이 아닙니다. launch 인자와 프로필이 겹치면 프로필 값이 우선하고 리허설 프로필은 실물 launch에서 거부합니다.

**아직 남은 범위:** 거리/IMU 측정 결과의 실제 토픽 보정 적용, 측정된 지연·노이즈를 가상 센서에 주입, IR 거리/ADC 보정표 UI, IMU 회전각 적분 비교, 시뮬레이터 체커보드 배치/이동 도구 및 전체 절차 자동 리허설. 현재 주기·노이즈 결과는 기록/분석되지만 적용된다고 표시하지 않습니다. 가상 카메라 K/D는 렌더러 기준이며 실제 왜곡을 그대로 렌더링하지 않습니다.

## 바닥 보드로 카메라 높이·기울기 추정

1. **카메라 내부 보정과 독립 검증을 먼저 통과**합니다. **장착** 탭에서 장착 확인에 사용할 보드의
   내부 코너 가로/세로 수와 한 칸 실측 길이(mm)를 따로 입력합니다. 내부 보정과 다른 규격의
   보드를 사용해도 됩니다. **장착 보드 설정 저장**으로 보존하며 촬영할 때도 현재 입력이 자동 저장됩니다.
   장착 보드 설정 변경은 내부 보정값·학습/검증 사진·이미 계산한 장착 기록을 무효화하지 않습니다.
2. 체커보드를 수평 바닥에 평평하게 놓고 로봇도 수평·정지 상태로 둡니다. 울거나 휜 출력물·두꺼운 받침을 피하세요. 보드 표면을 바닥으로 간주하므로 두꺼운 판 위에 놓으면 실제 바닥 높이와 차이가 납니다.
3. 장착 탭의 **보드를 바닥에 평평하게 놓고 로봇을 수평·정지시켰습니다**를 확인합니다. 보드 X/Y 위치, 0번 코너, 축 방향, base_link 높이는 입력하거나 등록하지 않습니다. 보드 전체 코너가 보이는지 미리보기로 확인합니다.
4. **바닥 보드 촬영 → 높이·각도 추정**을 누릅니다. 원본 사진 서비스로 새 사진을 받고 평면 IPPE PnP로 **바닥에서 카메라 광학 중심까지 높이**, 카메라 기계 프레임의 **좌우 기울기 roll / 상하 기울기 pitch**를 계산합니다. 화면에는 mm/deg, YAML에는 m/rad로 표시·저장하며 pitch 양수는 아래로 기울어진 방향입니다. 재투영 RMS >0.7px, 바닥 아래 해, 모호한 평면 해는 거부합니다.
5. 로봇을 고정하고 보드 위치/방향을 바꿔 **5회 이상 반복**합니다. 보드의 수평 방향과 코너 순서가 달라도 높이·바닥 기울기는 동일해야 합니다. `camera_mount`에 높이/roll/pitch 각각 평균·표본 표준편차·최댓값을 기록합니다. 5회 이상, 높이 표준편차 <5mm, roll/pitch 표준편차 각각 <0.035rad(약2°)이면 반복성 검사 통과입니다. 이는 정확도 보장이 아니며 모드/배치/내부 보정도 확인해야 합니다.
6. **결과·프로필 저장**으로 최종 결과를 보존합니다. 사진은 `floor/`, 회차별 값은 `results.yaml`의 `floor_camera`, 반복 통계는 `camera_mount`에 기록되며 `profile.yaml`에도 포함됩니다. 서비스 원본/CameraInfo·Bag/CSV·출처 메타데이터 보존 방식은 다른 촬영과 같습니다.

장착 탭을 선택하면 실시간 코너 미리보기도 **장착용 규격**을 사용합니다. 각 장착 사진의
코너 수·칸 길이는 해당 기록의 `board: [가로 코너, 세로 코너, mm]`에 고정하여 저장합니다.
나중에 다른 보드로 바꾸거나 사진을 추가해도, 과거 사진은 촬영 당시의 규격으로 재계산합니다.
프로젝트를 다시 열면 내부용/장착용 설정이 각각 복원됩니다. 이전 형식 프로젝트는 기존 공유 보드
규격을 장착 기본값과 과거 사진의 규격으로 계승합니다. 해상도·초점 조건은 내부 보정 당시와 같아야 합니다.

이 탭은 **높이·기울기 측정 전용**입니다. 로봇 기준 카메라 X/Y·yaw를 추정한 것으로 취급하지 않으며, 전체 `camera_pose`/TF를 만들거나 launch의 설치 위치를 덮어쓰지 않습니다. 기존 전체 pose 프로필과 저수준 등록 계산 API의 호환성은 유지합니다.

## 실물 자동 시간 동기화 (최초 1회 설정)

라즈베리파이를 로컬 NTP 서버로, PC를 그 클라이언트로 사용합니다. 인터넷 없이도 로봇과 PC의 **상대 시각**을 맞출 수 있지만 UTC 절대 정확도는 보장하지 않습니다. 아래는 각 장치의 해당 터미널에서 **한 번만**, 실험을 시작하기 전에 실행합니다. 로봇이 없는 개발 PC에서 robot 명령을 실행하지 마세요.

```bash
# 내용 확인만: 시스템을 바꾸지 않음
python3 scripts/setup_time_sync.py robot
python3 scripts/setup_time_sync.py pc

# 실제 라즈베리파이에서
sudo python3 scripts/setup_time_sync.py robot --apply
# 실제 사용할 PC에서
sudo python3 scripts/setup_time_sync.py pc --apply
```

도구는 chrony 설치·설정 백업·전용 conf.d 파일 생성·서비스 자동 시작을 수행합니다. 기본 로봇 주소는 192.168.4.1, 허용 네트워크는 192.168.4.0/24입니다. UDP 123이 통과해야 합니다. OS 설정은 UI/ROS 권한으로 강제 변경하지 않습니다. 설치 직후 큰 시계 차이의 수렴과 초기 시각 보정이 끝날 때까지 기다리세요. 기존 chrony의 초기 makestep 정책은 보존하며 실험 중에는 재설치/서비스 재시작을 하지 마세요.

설정 후에는 평소처럼 `robot.launch.py`와 UI를 실행하면 OS 서비스가 자동으로 동기화하고, UI에서 **real 모드를 선택하면 상태 확인도 자동**입니다. robot launch는 read-only chrony 상태 노드를 포함합니다. 누락·오래된 로봇 상태·다른 시간 서버·큰 추정 오차는 미동기화로 표시합니다. PC 시간이 동기화됐다는 bool 하나만으로 성공 처리하지 않습니다. 수집 중인 데이터를 소급해서 동기화된 데이터로 인정하지 않습니다. 현재 PC와 로봇에서는 실제 설정/동기화를 수행하지 않았으며, 코드와 합성 상태 응답만 검증했습니다.

구현 근거: [OpenCV 평면 PnP](https://docs.opencv.org/4.6.0/d5/d1f/calib3d_solvePnP.html), [chrony 구성](https://chrony-project.org/doc/4.5/chrony.conf.html), [chronyc 상태 조회](https://chrony-project.org/doc/4.5/chronyc.html).

## 범퍼 기준 공 위치 실측과 오프셋

공 인식 검토의 **범퍼 기준 실측 비교 · 검토용 오프셋**에서 실측 X/Y(m)와 오프셋 X/Y(m)를 입력합니다.
원점은 범퍼 전면 바깥 중앙의 바닥 투영점이며 X는 전방+, Y는 왼쪽+입니다. 실측 대상은 **공 중심**입니다.
정면 공의 앞쪽 표면까지 잰 경우 반경 21.35mm를 더해 중심 거리를 입력하세요.
표시는 인식−실측의 X/Y 오차·수평 거리·위치 오차와 오프셋 적용 후 값을 함께 제공합니다.
**현재 실측 차이를 오프셋으로**는 `실측−인식`을 입력란에 복사하며 `보정 표시 = 인식 + 오프셋`입니다.
입력/비교 저장만으로 현재 실행 중인 경기 노드나 TF는 변경하지 않습니다. 여러 거리·좌우 위치에서 확인하세요.
2026-11-27부터 명시적으로 내보낸 human_verified 프로필을 경기의 `ball_offset_source`로 선택하면
해당 `ball_review.offset_xy_m`을 base_link 축의 미터 보정으로 투영 후 한 번 적용합니다.
`auto`는 선택한 calibration_profile 또는 camera_yaml 옆 프로필, `none`은 기존 raw 투영입니다.
검토 UI의 `point`는 raw이고 아래 비교에서만 오프셋을 더하므로 중복 적용하지 않습니다.
**비교 기록 저장**은 프로젝트 `measurements.ball_review`에 관측 출처·모델 해시·실측·오프셋·오차를 보존합니다.
측정 기록 탭에서 확인/삭제/오차 통계 재계산이 가능하고, 프로젝트를 다시 열면 마지막 저장 입력을 복원합니다.
오프셋은 프로젝트 메타데이터 `ball_review.offset_xy_m`에 별도로 보존하며 비교 기록이 없어도 복원됩니다.
기존 보정 프로필은 비교 저장만으로 무효화하지 않습니다. 새 관측·실행 모델 범퍼가 필요하며 웹캠 모드에는 제공하지 않습니다.

카메라 높이를 모델값으로 지정한 프로젝트는 `meta.camera_mount_height_override`를 보존합니다.
장착 재계산 시에도 선택 높이를 적용하고 각도는 사진에서 측정합니다. 원래 높이 통계는
`results.camera_mount.measured_height_m`에 남으며, 검토 화면과 내보낸 프로필에는 선택 높이를 사용합니다.
