# Jupyter 카메라 보정 프로그램

**상태 (2026-11-20): 초기 프로토타입 보존용 문서입니다.** 사용자 요구에 따라 Jupyter 방식의
추가 개발은 중지했습니다. 이후 로봇의 상주 카메라 발행부와 PC 수신부로 연결할 예정이며,
그 연결은 아직 미구현입니다. 아래는 기존 구현의 실행 방법입니다.

**로봇 Wi-Fi 연결 → PC에서 프로그램 실행 → 연결 버튼**으로 시작합니다.
확인한 로봇 접속 주소는 `http://192.168.4.1:8888`, 카메라는 OV5647입니다.
로봇의 기존 `pinkylib.Camera`와 `calibration_camera()`를 사용합니다.
로봇에는 별도 프로그램을 설치하지 않고 PC에서 전용 임시 Jupyter 커널을 만듭니다.
다른 노트북의 코드나 커널을 변경하지 않습니다.

## 최초 설치와 실행

PC의 Ubuntu 24.04 / ROS 2 Jazzy에서:

```bash
cd ~/pinky-soccer
source /opt/ros/jazzy/setup.bash
rosdep install --from-paths src/pinky_soccer_calibration --ignore-src -y
./src/pinky_soccer_calibration/start_workbench.sh
```

빌드 없이 저장소의 최신 소스로 실행합니다. 설치 후에는 마지막 명령만 사용하면 됩니다.
이미 ROS Bag·OpenCV 관련 의존성이 설치된 개발 PC에서 GUI에 추가로 필요한 패키지만
설치하려면 다음을 사용할 수 있습니다.

```bash
sudo apt install python3-websocket python3-tk python3-pil.imagetk
```

일반 ROS 패키지 실행 방식도 지원합니다.

```bash
colcon build --symlink-install --packages-select pinky_soccer_calibration
source install/setup.bash
ros2 run pinky_soccer_calibration camera_workbench
```

주소와 PC 저장 위치를 바꾸려면:

```bash
./src/pinky_soccer_calibration/start_workbench.sh \
  --url http://192.168.4.1:8888 --output calibration_data
```

GUI의 주소·저장 폴더 입력란에서도 바꿀 수 있습니다. 인증이 필요한 Jupyter는 토큰을
화면의 별도 입력란에 넣습니다. 토큰은 파일·메모리 문서에 저장하지 않습니다.
토큰이나 비밀번호를 URL에 넣지 않습니다. 현재 확인한 로봇에서는 토큰 입력 없이 연결됐습니다.

## 1. 연결과 새 실험

1. 로봇 Wi-Fi에 연결하고 로봇 Jupyter에 접속되는지 확인합니다.
2. 다른 노트북에서 `cam.play_jupyter()` 등이 실행 중이면 그 노트북의 `cam.close()`를
   먼저 실행합니다. 이 프로그램은 다른 커널을 강제 종료하지 않습니다.
3. **연결**을 누릅니다. 확인된 기본 해상도는 **640×480**입니다.
4. 실측 칸 크기를 확인합니다. 사용자 확인값은 **30 mm**, 보드는 **가로 9 × 세로 6 내부 코너**입니다.
   칸 수는 10×7입니다. 실제 보드가 다르면 실측값을 입력합니다.
5. 카메라 식별명·저장 폴더·측정 메모를 입력하고 **새 실험**을 누릅니다.

각 실험은 PC에 `calibration_data/jupyter_날짜_시각_식별자/`를 만듭니다. 덮어쓰지 않습니다.
촬영 시작 후 칸 크기·식별명·해상도를 바꾸려면 새 실험을 시작하세요. 화면 입력을
바꾸는 것만으로 기존 실험의 기록을 수정하지 않습니다.

## 2. 학습 촬영과 내장 보정

평평한 판에 붙인 보드를 보여 줍니다. 코너 표시가 54개 교점에 맞는지 확인합니다.
선명도는 흔들림 점검용 지표이며 정확도의 단위가 아닙니다.

- **사진 저장** 또는 **Space**: 한 장 저장합니다. 입력란에서 Space는 글자 입력으로 동작합니다.
- **2초 간격 자동 촬영**: 검출·선명도 조건을 만족하는 사진을 저장합니다. 같은 버튼으로 중지합니다.
- 검출되지 않거나 흐린 사진은 저장하지 않고 안내합니다. 단계별 최대 80장입니다.
- 최소 **15장**, 권장 **25장 이상** 서로 다른 자세를 촬영합니다.

상하좌우, 가까운 거리·먼 거리, 좌우·상하 기울기를 고르게 바꿉니다. 움직인 후 잠깐
멈춰 촬영합니다. 보드 중심의 X/Y 촬영 범위 각각 25% 이상, 면적 최대/최소 비 1.5배 이상이
초기 목표입니다. 기울기도 적어도 15° 이상인 자세를 포함합니다.
같은 자세로 장수만 늘려서는 보정이 충분하지 않습니다.

**학습 보정 실행**을 누르면 로봇의 내장 `Camera.calibration_camera()`를
`checkerboard_size=(9, 6)`, `square_size=30`(또는 입력한 실측 mm)으로 호출합니다.
내장 함수가 영상마다 잠시 대기하므로 사진 수에 따라 수십 초 걸릴 수 있습니다.
처리 중에도 창은 응답하고, 카메라 접근 작업은 하나씩 실행합니다.

결과는 기존 검사 도구로 검증합니다. 평균·표본 표준편차·최대 RMS가 표시됩니다.
각 영상 RMS 기본 한계는 **0.7 px**입니다. 필요하면 실행 전에 명시적으로 변경할 수 있고
사용한 한계는 보고서에 남습니다. 낮은 오차만으로 실제 거리 정확도가 보증되지는 않습니다.

학습 검사가 실패하면 사진을 보완하고 다시 실행할 수 있습니다. 각 시도는
`attempt_001`, `attempt_002` 등으로 보존됩니다. 이미 찍은 사진을 지우거나 과거 보고서를
덮어쓰지 않습니다. 오차가 큰 사진을 제외해야 할 때는 새 실험으로 다시 촬영합니다.

## 3. 독립 검증과 결과 저장

학습 검사 통과 후 화면이 **독립 검증 촬영**으로 전환됩니다.
이때부터 학습 모델을 고정합니다. 새 자세의 사진을 **최소 8장**, 권장 15장 이상 촬영합니다.
검증 영상으로 다시 학습하지 않습니다.

1. **독립 검증 실행**을 누릅니다. 검증에서는 K/D를 고정하고 보드 자세만 추정합니다.
2. 실패하면 검증 사진을 보완하고 다시 검사합니다. 이전 검증 결과도 보존됩니다.
3. **보정 후 영상 보기**로 직선이 펴지는지 확인합니다. **사진·보고서 폴더 열기**에서
   `check/previews/`의 코너 표시와 왜곡 제거 영상도 확인합니다.
4. **코너·왜곡 제거 영상 확인 완료**를 체크하고 **검증된 결과 저장**을 누릅니다.

학습·검증 검사 통과와 시각 확인을 모두 요구합니다. 검증을 통과한 뒤 사진을 추가하면
다시 검증해야 합니다. 저장을 완료하면 Bag을 마무리하고 카메라와 전용 커널도 종료합니다.
각 실험 결과를 확인한 뒤 다음 외부 보정 단계로 진행합니다.

최종 파일은 `attempt_NNN/training/approved/`에 저장됩니다.

| 파일 | 용도 |
|---|---|
| `camera.yaml` | ROS CameraInfo 형식의 K/D/R/P |
| `camera_calibration.npz` | 내장 `Camera.set_calibration()`에 사용 가능한 원래 결과 |
| `calibration.yaml` | 검증 상태·보고서 경로를 포함한 통합 보정 스키마; 미측정 단계는 `null` |

NPZ에는 내장 함수가 계산한 보드 자세도 있지만 **`base_link` 기준 카메라 외부 보정값은 아닙니다**.
내장 함수의 `square_size`는 여기서 mm로 전달하므로 NPZ의 보드 tvec도 mm 기준입니다.
이후 제어·외부 보정에서 단위를 혼동하지 마세요. ROS 내보내기 YAML은 내부 K/D/R/P만 담습니다.

## 원본 보존과 반복 통계

| 위치 | 내용 |
|---|---|
| `experiment.yaml` | 사용자 입력, 카메라 설정·방향, 단위, 시각 출처 |
| `calibration/*.png`, `validation/*.png` | 로봇에서 받은 무손실 원본 배열 |
| 같은 이름의 `*.jpg` | 내장 함수 입력용 JPEG 품질 100; PNG도 함께 보존 |
| `samples.csv` | 샘플별 로봇 관측 시각·PC 수신 시각·선명도·파일 경로·해시 |
| `raw_bag/` | **저장한 샘플**의 원본 bgr8 Image; 미리보기 전체 스트림은 포함하지 않음 |
| `attempt_NNN/training/native/` | 내장 함수 입력을 동일 픽셀 PNG로 보존한 검사 입력, 원본 NPZ·ROS YAML |
| `attempt_NNN/*/check/` | 코너별 잔차 CSV, 영상별 RMS CSV, 보고서 YAML, 확인 영상 |

ROS Bag 토픽은 `/calibration/calibration/image_raw`, `/calibration/validation/image_raw`입니다.
헤더 시각은 `get_frame()` 직후 로봇의 시스템 시각이며 정확한 센서 노출 시각이 아닙니다.
PC 수신 시각은 CSV에 따로 남깁니다. 가상의 ROS 카메라 토픽을 실물 발행 토픽으로
표기하지 않습니다. Bag과 PNG는 같은 수신 배열을 보존합니다.

각 실험을 새로 촬영하여 3회 이상 반복하는 것을 권장합니다. 반복 통계는 기존 CLI로:

```bash
ros2 run pinky_soccer_calibration camera_intrinsics summarize \
  --reports <첫실험>/attempt_001/training/check/report.yaml \
            <둘째실험>/attempt_001/training/check/report.yaml \
            <셋째실험>/attempt_001/training/check/report.yaml \
  --output calibration_data/repeat_summary.yaml
```

검증 보고서도 함께 확인해 사용할 모델을 선택합니다. 평균 모델을 자동으로 적용하지 않습니다.

## 방향·적용·종료

`pinkylib.Camera.get_frame()`은 영상을 **180° 회전**합니다. 이 프로그램은 그 영상을
그대로 보정합니다. NPZ는 동일한 `get_frame()` 흐름에 사용할 수 있습니다.
ROS 드라이버의 회전하지 않은 영상에 같은 YAML을 그대로 적용하면 안 됩니다.
해상도·crop·방향이 달라지면 별도 보정하거나 검증된 좌표 변환이 필요합니다.
프로그램은 기존 URDF, 제어 설정, 로봇 라이브러리와 다른 노트북을 자동 변경하지 않습니다.

**연결 해제**, 창 닫기, 검증 결과 저장 시 카메라를 닫고 자신이 만든 커널만 종료합니다.
Wi-Fi가 끊기면 로봇 쪽 유휴 감시가 마지막 작업 후 약 30초에 카메라를 해제합니다.
통신이 끊겨 커널 삭제 요청이 실패하면 임시 커널이 Jupyter에 남을 수 있습니다.
다시 접속한 뒤 Jupyter의 실행 중 커널 목록에서 해당 임시 커널을 확인하세요.
정상 종료 시 기존 노트북 커널은 유지됩니다.

로봇에는 해당 실험의 내장 함수 입력 JPEG가 `/tmp/pinky-calibration-*`에 임시 보존됩니다.
프로그램은 원본을 임의 삭제하지 않습니다. PC에 백업을 확인한 뒤 필요하면 직접 정리하세요.

연결이 끊기거나 종료된 실험의 촬영 재개는 지원하지 않습니다. 새로 연결하고 새 실험을
시작합니다. 이미 저장된 원본·검사 보고서는 남고, 완료된 학습·검증 보고서의 내보내기는
기존 `camera_intrinsics export`로도 할 수 있습니다. 강제 종료 시 Bag 메타데이터가
없으면 `ros2 bag reindex <실험>/raw_bag`로 복구를 시도할 수 있습니다.
