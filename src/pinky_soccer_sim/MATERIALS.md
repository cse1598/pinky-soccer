# 골프공 · 폼 매트 · 고무바퀴 공통 물성

`config/materials.yaml`이 두 시뮬레이터의 런타임 물성 원본입니다.
`game.launch.py mode:=mujoco|gazebo`와 각 시뮬레이터 launch 모두 기본 적용합니다.
실행 중인 시뮬레이터에는 소급되지 않으므로 종료 후 다시 실행하세요.
공식 `pinky_pro`는 수정하지 않고 자체 어댑터가 생성 모델에 적용합니다.

## 근거와 가정

- 골프공 지름 **42.7mm**는 사용자 실측입니다. R&A 규격은 지름 최소42.67mm,
  질량 최대45.93g입니다. 질량 **45.9g**을 일반적인 규격 공의 대표 초기값으로 유지합니다.
  규정 상한을 제품 실측으로 취급하지 않습니다.
  [R&A](https://www.randa.org/en/roe/the-rules-of-equipment/part-4-conformance-of-balls)
- 공은 고무 코어/폴리머 커버 제품을 유효 균질 구로 근사하며 관성은 `I=0.4mr²`입니다.
  단단한 표면 반발0.80은 참고 가정이며 폼 바닥에 그대로 사용하지 않습니다.
  골프공 낙하 연구는 충돌 속도와 상대 표면에 따른 반발 차이를 보여 줍니다.
  [스포츠 공 낙하 실험](https://doi.org/10.1088/1757-899X/36/1/012038)
- 바닥은 **일반적인 폐쇄기포 EVA 계열 폼 요가매트**, 구동바퀴는 **건조 고무 트레드**를
  가정합니다. 사용자 매트가 NBR/TPE/PVC인지, 실제 두께·경도·표면 무늬는 아직 미확인입니다.
  EVA 요가매트와 폼 압축 연구는 이런 근사를 뒷받침하지만 아래 숫자를 제공한 것은 아닙니다.
  [요가매트 소재 연구](https://doi.org/10.1002/pls2.10050),
  [EVA 폼 압축 연구](https://pmc.ncbi.nlm.nih.gov/articles/PMC10780418/)
- **정확히 같은 골프공/매트/바퀴 조합의 공개 실측값은 확보하지 못했습니다.** 따라서 아래
  마찰·강성·반발·구름 저항은 명시적인 공학적 초기 가정입니다. 재질 이름만으로 유일한 값을
  알 수 없으며, 실측 전에는 실제 장비와 같은 움직임이라고 주장하지 않습니다.

| 접촉쌍 | 미끄럼 마찰계수 | 목표 반발계수 | 유효 스프링 N/m | 구름 감속 기준 m/s² |
|---|---:|---:|---:|---:|
| 골프공–폼 바닥 | 0.45 | 0.25 | 1500 | 0.35 |
| 고무 구동바퀴–폼 바닥 | 0.90 | 0(임계 감쇠) | 12000 | 0.02 |
| 캐스터–폼 바닥 | 0.10 | 0(임계 감쇠) | 8000 | 0.01 |
| 골프공–벽/골대 상자 | 0.35 | 0.60 | 15000 | 0 |

강성은 접촉점의 **유효 N/m**이며 EVA의 Young's modulus(Pa)가 아닙니다.
바닥은 고정체이므로 밀도로 질량을 만들어 넣지 않습니다. 기존 바퀴의 형상·질량·관성은
공식 URDF를 유지합니다(전체 바퀴를 속이 찬 고무 구로 바꾸지 않음).
감쇠 계산의 유효 질량은 바퀴0.20kg/캐스터0.10kg의 초기 근사이며 공은 실제 실행 공 질량입니다.
구름 저항은 미끄럼과 별개입니다. 공의 기준 감속은 정상 하중에서의 순수 구름 값이며,
골프 퍼팅 연구의 측정 방법을 참고했지만 잔디의 값을 폼 실측값으로 전용하지 않았습니다.
[구름 저항/퍼팅 모델](https://raypenner.com/golf-putting.pdf)

## 두 엔진에서 같은 계산 적용

`src/contact_kernel.cc`를 공유 라이브러리로 한 번 빌드합니다. Gazebo 시스템 플러그인과
MuJoCo Python 어댑터(`ctypes`)가 **그 라이브러리의 같은 함수**를 호출합니다.

1. 실제 충돌 구의 중심·반지름과 속도·각속도를 사용합니다. 바퀴 크기를 보정한 URDF도 반영합니다.
2. `N=max(0, k×침투량−c×수직속도)`의 한쪽 방향 스프링·댐퍼를 적용합니다.
3. 표면 미끄럼 속도(병진+회전)에 반대되는 Coulomb 마찰을 `μN` 및 시간 간격별
   관성 한도로 제한합니다. 구름 저항 토크는 정상 하중에 비례하며 역회전을 유발하지 않게 제한합니다.
4. 양쪽 모두 **1ms 물리 시간 간격**, 같은 중력·마찰·강성·감쇠 변환을 사용합니다.
   반발 목표는 이산 단방향 스프링 응답으로 감쇠에 변환합니다. 낙하가 시간 격자의 어느 지점에서
   접촉하느냐에 따라 실제 반발은 목표와 조금 다를 수 있습니다. 바퀴0은 임계 감쇠의 의미이며
   수치적인 미세 반발을 완전히 없앤다는 뜻은 아닙니다.
5. 공/바퀴–바닥과 공–정적 상자 접촉은 네이티브 충돌에서 제외해 **힘을 두 번 적용하지 않습니다**.
   전복 시 차체–바닥, 로봇–공/벽, RCJ 경사면 메시 등의 충돌은 원래 엔진이 담당합니다.

현재 평면 매트와 정적 상자에 대한 유효 접촉 모델입니다. 매트 전체가 시각적으로 휘어지는
유한요소/연체 모델은 아닙니다. Gazebo DART와 MuJoCo의 관절·모터 제어·메시 충돌까지 동일한
엔진으로 바꾼 것은 아니므로 전체 로봇 궤적이 비트 단위로 같지는 않습니다.
`field.yaml`의 치수/원점은 유지하고, 생성 자산에 남은 예전 `friction: 0.8`보다 이 런타임 설정이
우선합니다. `ball.friction_tau`는 월드모델 예측 값이므로 물리 엔진 설정과 자동으로 혼동하지 않습니다.

## 변경과 검증

```bash
source /opt/ros/jazzy/setup.bash
colcon build --packages-select pinky_soccer_sim --symlink-install
source install/setup.bash

ros2 launch pinky_soccer_sim mujoco_soccer.launch.py field:=hardboard
# 또는
ros2 launch pinky_soccer_sim gazebo_soccer.launch.py field:=hardboard
```

별도 설정은 두 시뮬레이터에 같은 파일을 지정합니다.
`material_config:=/절대경로/materials.yaml`. 실제 런타임 SDF/MJCF만 바꾸며 원본 모델은 보존합니다.
지원하지 않는 시간 간격/강성 조합은 로드할 때 거부합니다.

```bash
# 기존 로봇/시뮬레이터를 제어하지 않고 격리한 물리 시험을 생성·종료합니다.
ros2 run pinky_soccer_sim check_material_physics --output /tmp/my-new-material-test
```

출력 폴더는 새 경로여야 하며 각 실험의 MuJoCo/Gazebo 원본 `CSV`와 설정·결과·통과 기준의
`report.json`을 보존합니다. 20cm 낙하, 1m/s 순수 구름, 공–벽1m/s 충돌을 비교합니다.
엔진 간 허용차는 반발계수0.03, 정지 거리0.03m, 벽 반사 속도0.06m/s이며,
두 엔진이 함께 잘못되는 경우를 막기 위해 설정 목표와의 차이도 검사합니다.
이것은 엔진 간 일치 시험입니다. 실제 매트에서 낙하 높이/반발 높이·정지 거리·직진/회전 궤적을
별도로 측정해 이 초기 프리셋을 갱신해야 실물 검증이 됩니다.

2026-11-22 기본 프리셋 검증 결과(설정 목표와의 허용차 포함 모두 통과):

| 시험 | MuJoCo | Gazebo |
|---|---:|---:|
| 20cm 낙하 반발계수 | 0.210155 | 0.210155 |
| 1m/s 순수 구름 정지 거리 | 1.428078m | 1.429077m |
| 벽 충돌 후 X속도 | −0.592647m/s | −0.592647m/s |

낙하 목표0.25와 실제0.210의 차이는 이 접촉 강성·1ms 격자에서 관측된 수치 오차입니다.
이를 실제 폼 매트의 실측 반발값으로 저장하지 않습니다.

실제 로봇 모델의 직진·정지와 범퍼 공 밀기도 확인했습니다. `0.1m/s`를 약2초 명령한
직진 거리는 MuJoCo 약0.184m, Gazebo 약0.194m였습니다. 공식 모터 제어기의 토크/속도 응답은
서로 달라 유지한 상태이며, 공통 재질 설정만으로 전체 주행 궤적까지 같아지지는 않습니다.
회귀37개·새 모듈 lint·빌드 및 양쪽 경기 카메라/공 좌표 출력 검증을 통과했습니다.
